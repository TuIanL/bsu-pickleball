## 三、P1 级问题（后端，建议本轮修）

### P1-B1 `_heartbeat_loop` 租约丢失会停掉整个 worker 主循环 ★

**位置**：`job_orchestration.py:1253`、`:1259`

```python
if not run_id or not self.store.heartbeat(job.id, run_id):
    failed_event.set()
    self._stop_event.set()   # ← 停的是 worker 主循环，不是 heartbeat
    return
```

**已 grep 确认 `_stop_event` 的全部用法**：`:1167` 创建、`:1176` clear、`:1185` `stop()` 用、`:1220` `_loop` 主循环 `while not self._stop_event.is_set()`、`:1253`/`:1259` 此处。

`_stop_event` 的语义是"**整个 worker 该关停**"（`:1185` 的 `stop()` 也用它），用它表达"这一个 job 丢了租约"是错的 —— 一旦置位，**worker 主循环永久退出、不再领取任何后续任务**。

**触发条件**：任何一次 `store.heartbeat` 返回 False。包括**用户取消一个正在运行的任务**（job 进终态 → `mutate` 的 `expected_status="running"` 失配）、SQLite busy 超时。

**后果**：单个任务的操作导致全局服务降级；embedded 模式（`main.py:47` lifespan 只启动一次）**不可自愈**。

**修复**：删掉 `:1253`/`:1259` 的 `self._stop_event.set()`，只保留 `failed_event.set()` —— `failed_event` 已在 `:1321`/`:1446`/`:1457` 被正确检查，足够表达"租约丢失"。若确实需要退出 worker，应新增独立 `_fatal_event`。

### P1-B2 `WorkerLeaseLostError` 被 pipeline 吞成"分析任务失败" ★

**位置**：`analysis_pipeline.py:571`（try 起）、`:594`（`except Exception as exc`）

### P1-B9 SQLite 主库未启用 WAL，并发写会 `database is locked`

**位置**：`backend/app/database.py:40-44`

```python

    f"sqlite:///{db_path}",
    connect_args={"check_same_thread": False},
    echo=False,
)
```

**运行时实测证据**：

| 库 | journal_mode | busy_timeout |
|---|---|---|
| `data/app.sqlite3` | **delete** | 5000 |
| `data/analysis_control.sqlite3` | **wal** | 5000 |

**问题**：WAL + `busy_timeout=30000` 只在 `services/analysis_control_plane.py:31-33` 一处设置（即分析控制面专库）。主库 `app.sqlite3` 走 SQLAlchemy 默认的 rollback journal，**多线程并发写会直接抛 `database is locked`**。

这不是理论风险：项目同时存在 FastAPI 线程池、`analysis_worker` 线程、录制线程、`_POSTER_EXECUTOR` 线程池，多个组件并发写 `capture_takes` / `capture_tracks`。

同一项目两套 SQLite 配置不一致，说明 WAL 是某次局部改动的顺带产物，缺少统一入口。

**修复**：把 PRAGMA 收进 `get_engine()`，对所有库统一施加。

```python
@event.listens_for(_engine, "connect")
def _set_sqlite_pragmas(dbapi_connection, _record):
    cursor = dbapi_connection.cursor()
    cursor.execute("PRAGMA journal_mode=WAL")
    cursor.execute("PRAGMA busy_timeout=30000")
    cursor.execute("PRAGMA synchronous=NORMAL")
    cursor.close()
```

注意：外接盘上的 SQLite **不适合开 WAL**（WAL 依赖共享内存 `mmap`，USB/外置卷上可能失效甚至损坏）。若 `app.sqlite3` 可能落在外接盘，需按路径分支处理，或明确约束主库必须本地。
