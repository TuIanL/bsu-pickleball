## 三、五个顶层判断

### 判断 1：答辩口径存在"自相矛盾"硬伤，且是最高 ROI 的修复项

已砍掉的 TENG-IMU 智能球拍方案**在三个对外可见的地方仍然活着**：

| 位置 | 内容 |
|---|---|
| `README.md:3` | 「基于视觉捕捉与 **TENG-IMU 智能球拍**的匹克球全维度分析平台」 |
| `README.md:183` | `├── HardwarePage.tsx  # 智能球拍硬件介绍` |
| `src/app/router.ts:51, 253-254` + `AppRouter.tsx:79` | **`/hardware` 路由真实可达**，手输 URL 即进入 |
| `src/pages/HardwarePage.tsx:11, 28` | 页面自认「二期硬件融合」「模拟数据」 |

而 `docs/瞬境_技术成果说明.md:4` 明确写着「智能球拍（TENG-IMU）硬件方案**已不属于**本项目交付范围」。
**风险**：评委按 README 索引或手输 URL 进入该页，直接形成"材料口径不一致"的印象——这在竞赛场景是致命的，而非技术瑕疵。

### 判断 2：demo 兜底会伪造"分析成功"的任务，威胁数据真实性自证

`analysisClient.ts:715` 在后端失败时 `throw`，但 `:721` 随后调用 `buildMockJob()` **伪造一个任务**；`:734`/`:740` 在后端返回空数组**和**抛异常两种情况下都回落到 localStorage。

**这对你尤其危险**：本项目同时是科研实验平台，你的方法论底线是"拒斥合成证据伪装为真实"。当前实现会在后端 500 / 断连时，让用户看到一条"分析完成"的绿条任务，而数据来自 `demoData.ts`。评委问「这个数据是真的算出来的吗」，前端无法自证。
**这不是 demo 模式的便利性问题，是真实性边界被代码抹掉了。**

### 判断 3：OpenSpec 工作流"看起来规范，但已出现实质漂移"

- **规格违约（实锤）**：`openspec/specs/projection-diagnostics/spec.md:38-40` 规定
  > **WHEN** `enable_projection_debug_jsonl` 为 False → **THEN** 系统 SHALL NOT 生成 JSONL 文件 **AND** SHALL NOT 产生额外 I/O 开销

  而 `analysis_pipeline.py:1886-1896` **无条件** `ProjectionDebugWriter(...).open()` 并逐帧写盘。配置项 `config.py:120-121` 全仓**无任何读取点**（只在 config 里定义与读 env）——即"设计有开关、实现忘了接"。spec 与代码已经分叉，且这个 change 早已归档。
- **规格资产空心化**：`openspec/specs/` **74 / 185** 个 capability 的 Purpose 仍是 `TBD - created by archiving`（40%）。
- 结论：OpenSpec 流程形式完备（190 个归档、命名统一、当前活跃 change 任务 36/36 完成），但**"归档即完结"没有反向校验代码是否真的遵守 spec**。建议归档前增加"spec 场景 → 代码断言"的对照检查。

### 判断 4：性能问题不是"慢一点"，而是随数据量线性劣化

最严重的一条链路（已逐帧核实）：

```
analysis_pipeline.py:464/478/489/625/... 每帧 _check_cancelled()
  → job_orchestration.py:3269 raise_if_cancelled()
  → :884 is_cancel_requested() → store.get(job_id)
  → :470 JobStore.get() 无条件调用 _import_legacy_jobs()
  → :360-369 对 jobs_dir.glob("*.json") 全量读取 + pydantic validate + 逐条 SQL insert_if_missing
```

1 万帧视频 = 数万次 ×（27 次文件读 + 27 次 pydantic 校验 + 27 次 SQL），且发生在视频解码热路径上、与 heartbeat 线程抢 SQLite 写锁。**job 越多越慢**，这不是常数开销。

### 判断 5：可复现性对科研项目是硬要求，当前不满足

- `backend/requirements.txt` **零版本锁定**（`==` 计数为 0，全为 `>=`），`torch`/`mmpose`/`mmcv` 只存在于注释中。
- 根 `pyproject.toml:5` `dependencies = []` 是空壳，真实依赖在 `backend/requirements.txt`——**双真相源**。
- 模型权重 `models/` 下只有 README 被 git 追踪，`*.pt` 全被忽略且**无下载脚本**；`start-local-runtime.sh:170-176` 硬性校验 checkpoint 存在 → **新人克隆后必然启动失败**。

对"科研实验平台"这一定位而言，`numpy<2.0` 跨小版本行为差异会直接改变分析结果，这是比性能更难被发现的隐患。
