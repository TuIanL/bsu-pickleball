## Context

动作分类模型（baseline4：volley / dink / drop_shot / forehand_drive）已在独立仓库完成训练与评估，权重是三个 LOSO 折模型（每折在另外两个来源上训练）。主系统目前只把 `stroke.classify` 声明为 planned，`ShotEvent.stroke_type` 从未写入。

三条既有事实约束了设计：

1. **姿态已落盘**：单摄 `AnalysisPipeline` 会写出 `pose_overlay.json`（26 点、源码像素、逐帧、带 `track_id`/`bbox`/`confidence`/`visible`）。双摄的 parent 没有姿态产物，但两个 child job 各自有。所以推理的输入不需要重新跑视觉。
2. **两处一阶落差已量化**：按双摄七场真实框高分布扰动，现成权重 Macro-F1 从 0.547 掉到 0.366（尺度）；把窗口从 `clip_extent` 换成 `[b,e]`，冻结权重 −0.004（窗口）。
3. **模型没见过"选人"**：训练集每条只有一个被人工裁好的击球人，四类标签之外没有"其他人是谁"的负样本。击球人归属必须是独立步骤，不能指望分类器顺手解决。

## Goals / Non-Goals

**Goals:**

- 让任一已有分析任务能一键产出逐次挥拍的动作事实，并可复现、可追溯
- 在模块边界上消掉尺度落差，使现成权重在系统机位上恢复到接近原生水平
- 明确"不知道就不猜"：类外样本、低置信度、姿态残缺一律走弃判，不强行归四类
- 不改动 12 阶段状态机与既有 API 行为

**Non-Goals:**

- 不训练新模型、不做微调（属后续 change）
- 不引入球轨迹为硬依赖，不修改 `shot-rally-events.v1` 契约
- 不覆盖四类之外的击球（发球、反手、杀球、挑高）
- 不做实时推理；只对已完成分析任务做后处理
- 不改造双摄融合链路去补姿态

## Decisions

**D1：形态为后处理模块，不进管线阶段**

读 `pose_overlay.json` + 可选回合片段，产出独立 artifact。备选是"在 `analysis_pipeline.py` 里加第 13 阶段"或"注册成 `analysis_runtime` 的 capability 节点"。放弃原因：前者要动 2400 行的主链路且双摄 child/parent 口径不一致；后者受 `run_capability` 的逐帧契约限制（`iter_frames`），窗口级能力需要另加 runner，收益不抵成本。后处理形态的额外好处是历史任务可回放。

**D2：尺度归一在推理前做，不改特征定义**

对每名球员、每个窗口，取窗口内 bbox 高度的中位数 `h`，把该球员所有关键点坐标乘以 `254 / h`（254 px 为训练素材框高中位），再算 41 维特征。这样带 px 量纲的 15 维回到训练分布，冻结权重可直接用。

备选是"把特征改成无量纲（除以框高）并重训"——更彻底，但会推翻 0.606 的可比性且需要新数据。选择前者的理由是：它是**可逆的参数**，产物里记录 `scale_factor` 就能追溯；后者是不可逆的口径变更。

细节：`h` 用中位数而非单帧，避免姿态抖动；缩放因子 clamp 到 `[0.5, 2.5]`，超出视为异常并降级为弃判。

**D3：窗口默认对齐 `clip_extent`，不采用 `[b,e]`**

冻结权重在 `[b,e]` 上无收益（−0.004），说明它吃到的是"含前后缓冲的整段"约定。因此推理窗口定为"触球候选前后固定缓冲"（起始 ≈ 触球前 0.6 s、结束 ≈ 触球后 0.4 s，具体帧数由 `fps` 换算并 clamp 到片段边界）。`[b,e]` 只在未来重训时启用，届时同步切换 `window_policy`。

**D4：挥拍检测用相对阈值，不用绝对 px/s**

对每名球员计算腕速序列，以该球员自身速度分布的稳健分位（如 p90）为基准设阈值，峰值超阈值且满足局部极大（非极大抑制窗口约 0.4 s）即为挥拍候选。理由：绝对 px/s 会随尺度与机位漂移，D2 之后虽有校正，但仍以相对量更稳。

**D5：击球人归属用候选打分 + 允许并列**

候选特征：归一化腕速峰值、腕到球距离（球轨迹可用时，默认不启用）、回合内 A/B 侧交替约束。取分数最高者为 `hitter`；若前两名分差小于阈值，返回并列候选并标记 `ambiguous`，不强制单选。多人同时挥拍（多球/热身）走同一路径。

**D6：三折集成 + 显式弃判**

三个折模型分别输出概率，取均值作为最终概率，**折间分歧度**作为不确定性度量，写入 `evidence_sufficiency`。弃判条件（任一满足）：最大概率低于阈值、折间分歧度高于阈值、`valid_frame_ratio` 低于阈值、窗口长度不足。弃判时类别写 `unclassified`，置信度保留。

**D7：权重以树结构导出，由纯 numpy 求值**

不把 `xgboost` 引入产品运行时。79 KB 级别的浅树（41 维、四类）导出为紧凑 JSON，用约百行 numpy 遍历实现，配一个等价性测试：在固定样本集上与原 `xgboost` 预测逐条比对，要求类别完全一致、概率误差 < 1e-6。备选是直接装 `xgboost`（省事，但给产品后端加约 200 MB 依赖和一条原生库链），在演示与部署环境不可控的前提下不值得。

**D8：身份归属分两级，允许降级**

优先把机位本地 `track_id` 归到 `Player_N`（复用名册绑定与融合产物的 `view_observations`）；归属不可用时降级输出本地 `track_id` 并标 `identity_scope: local_track`，不猜测、不硬映射。理由：本项目已明确禁止单帧距离改身份。

**D9：产物独立，暂不回写 `ShotEvent.stroke_type`**

本 change 只写 `action_classification.json`。回写 shot 事件会把本模块与球轨迹装配链耦合，而球轨迹目前不是可信输出。列为 open question。

## Risks / Trade-offs

- [尺度归一依赖 bbox 质量：姿态失败或框抖动时缩放因子失真] → 用窗口中位 + clamp；`valid_frame_ratio` 过低直接弃判；产物记录 `scale_factor` 供排查
- [远端球员仅约 108 px，腕速噪声大，分类不可信] → 设最小框高门槛（如 150 px），低于门槛只出检测不出类别；双摄优先用较近机位（174）
- [四类只覆盖网前与正手抽球，真实回合大量击球落在类外] → 弃判为默认路径；界面上把 `unclassified` 作为正常结果展示而非错误
- [冻结权重对姿态重提取敏感（同素材重跑姿态即掉 0.06）] → 产物记录姿态来源与 `keypoint_schema`；跨 job 比较时先校验姿态来源一致
- [窗口与训练口径不完全可复刻：`clip_extent` 是人工剪辑习惯] → 用固定缓冲近似，并以 `window_policy` 字段显式声明；接受这部分残余误差，不用调参去拟合
- [三折集成的分歧度不是校准过的概率] → 只作为相对不确定性，不对外称"置信概率"

## Migration Plan

1. 离线原型先在 `take_sync_20260720_122645_317228` 的两个 child job 上跑通，人工核对输出合理性
2. 落地 service 与端点，默认关闭（配置门控），仅在显式调用时执行
3. 前端入口上线后再打开门控；产物读取失败时界面降级为"暂无动作分类结果"，不阻塞既有报告
4. 回滚：删除端点与产物文件即可，主链路无改动，无数据迁移
