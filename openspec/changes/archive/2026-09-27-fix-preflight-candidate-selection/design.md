## Context

预检引擎 `backend/app/services/player_bootstrap_preflight.py` 是纯逻辑模块（帧源、检测器、投影器全部注入，不 import cv2/ultralytics），负责在所选片段内做有界多窗口采样，产出单打两名 / 双打四名候选，交给确认页冻结名册。

现状（`take ct_9997fa5aedf7`，clip=全片 0–587166ms，实测复现）：

- 采样 16 帧（8 个时刻 × 2 机位），覆盖 289.083–296.083s。
- 12 条 cam_1 轨迹 + 12 条 cam_2 轨迹 → 13 条通过门槛（另有 8 条判场外）。
- 最终选取阶段 4：把分数前 8 名按 `first_center[0]`（首帧画面 bbox 中心 x）重排取最左 4。结果综合分 0.9306 的近端真实球员（canonical 脚点 (16.08, 44.84)，全场第 2）被挤出；入选的是综合分 0.6144、命中 2 帧、无跨机位佐证的重复轨迹。
- 重复轨迹的成因：f17405 上检测器对同一名远端球员给出两个重叠框（中心 (1104,98) conf 0.37 与 (1117,97) conf 0.64）。关联规则是"一条轨迹在同一时刻至多吸收一个检测"，第二个框无人认领 → 新建轨迹 T11。此后 290083 / 291083 / 292083 三个时刻里，该球员只产生一个检测，T2 与 T11 交替抢到（0.016 vs 0.0114 vs 0.0099），两条轨迹各自虚增命中。
- 现有同帧去重要求 `first_frame_index` 完全相同且 IoU ≥ 0.5；T2（f17345）与 T11（f17405）首帧不同，结构上覆盖不到，实测 IoU 仅 0.15。

约束：

- 预检引擎必须保持纯逻辑与显式注入，不能为本次改动引入 cv2/ultralytics 依赖。
- 正式 tracking 管线已有一套分侧语义可复用：`player_lock_manager._BootstrapTracklet.inferred_side(half_length)` 用 court_y 中位数 + `SIDE_DEAD_ZONE_FT = 2.0` 判定 near/far/None；`primary_player_selector` 用 `near_side_quota=2 / far_side_quota=2` + `PlayerGroupProfile` 做配额收尾。预检当前只抄了 `court_margin_ft=12.0` 一个数，没有任何分侧概念。
- 既有规格 `automatic-player-roster-candidates` 已承诺"不得仅因同一帧检测到预期人数就把所有人认定为参赛球员""不得为了凑满四人选入场外人员"——本次改动是让实现回到该承诺。

## Goals / Non-Goals

**Goals:**

1. 四人选取以证据为准：删掉"首帧画面 x 取最左 4"，改为证据排序 + 赛制分侧配额（双打 2+2、单打 1+1），使"同队两人同侧"的球场结构直接体现在建议槽位里。
2. 同一名球员在一次预检中至多产生一个候选：新增同机位跨帧同人合并，覆盖"检测器同人多框 → 关联拆轨 → 交替抢检测"这一失效模式。
3. 分侧判据复用正式管线既有语义，不新造第二套定义。
4. 一侧证据不足时诚实降级，不跨侧补位，并给出可核对的诊断。
5. 保持确定性：同一输入（视频版本 + 片段 + 同步/标定 + 模型 + 配置）产生同一候选顺序与同一 `cache_key`。

**Non-Goals:**

- 不修 `court_margin_ft = 12.0` 过宽导致相邻场人群入候选（实测距场 10.6ft 仍被判"场内"）——独立事项。
- 不修源视频 `cv2.VideoCapture` 重复打开导致的冷请求耗时（实测外接盘单次 open 9.7–13.4s）——独立事项。
- 不修抽帧预算按"时刻 × 机位"计费、相邻窗口共享端点时刻被去重导致实采 16 帧而非 20 帧的记账问题——独立事项。
- 不做"轨迹断裂后重新起轨（A 结束、B 在后来的时刻开始）"的跨时间断桥合并。
- 不做跨机位（cam_1 ↔ cam_2）的轨迹合并——该路径已由既有跨机位去重承担。
- 不改正式 tracking 管线、不改预检 API 路由形状、不改前端组件。

## Decisions

### D1 选取：证据排序 + 赛制分侧配额，槽位按 canonical 端分组

排序键：`(机位优先级, -综合分, 首帧时刻, 首帧中心 x, 首帧中心 y)`——即沿用既有 `_score_tracklet` 的综合分作为主键，画面位置只作为同分时的稳定兜底键。

选取：按 `match_format` 的期望人数拆配额（双打 2+2、单打 1+1），在每一侧内部按上述顺序取满配额。

槽位编号：`canonical y < 22ft` 的一侧（A 端）→ P1、P2；`canonical y > 22ft` 的一侧（B 端）→ P3、P4；每一侧内部按首帧中心 x 升序。这样"P1P2 一边、P3P4 另一边"直接成立，且与确认页既有的"Team A 位于 A 端 / B 端"用同一套端点命名，不引入第二套词汇。

为什么不用"按综合分取前 4"（最小改动方案）：单人分数最高但同侧占满 3 人时，前 4 名仍会给出 3+1，症状不变。

为什么保留首帧中心 x 作为槽位内排序键：它只是**同侧内部**的稳定排序，不再参与"谁入选"，因此不会像现在这样让画面位置压过证据；对使用者也更符合"从左到右"的直觉。

### D2 同人合并：同机位、时间互斥 + 永不分离

在采样与逐帧吸收完成之后、选取之前，对每个机位做一次轨迹合并后处理（不动逐帧吸收规则本身）：

对同一机位的两条轨迹 A、B：

- 令 `exclusive(A,B)` = 采样时刻中"恰有一方有观测"的时刻数。
- 令 `shared(A,B)` = 两方在同一时刻都有观测的那些时刻的归一化中心距离。
- 令 `nearest(A,B)` = 对 A 的每个观测，在 B 的观测中取 `|Δt| ≤ max_association_gap_ms` 内最近时刻的距离，按时间配对后的最小值（反之亦然）。

合并条件（全部满足）：

1. `exclusive(A,B) ≥ min_exclusive_observations`（默认 2）——两者反复互斥出现，说明它们在同一时刻争夺同一个检测；
2. `nearest(A,B) < merge_radius_normalized`（默认 0.08）**且** `max(shared(A,B)) < merge_radius_normalized`——两者从未分开过；
3. 若双方都有外观描述子，则外观距离必须 ≤ `merge_appearance_max_distance`（默认 0.3，作为**否决**条件：明显不同则不合并；描述子缺失时不参与判定）。

为什么以"时间互斥"为主判据：真正的两名队友在几乎每个采样时刻都会各自被检测到（`exclusive ≈ 0`），而"同一人的单个检测被两条轨迹轮流认领"必然产生 `exclusive ≥ 2`。这一条把"站位很近的两名队友"与"被拆开的同一个人"区分开，仅靠距离做不到（远端 7ft ≈ 0.10 归一化，仍在关联半径 0.15 内）。

为什么合并半径（0.08）比关联半径（0.15）小：合并是不可逆的身份断言，误合并会把两名队友并成一名；收紧到 0.08 后，本案例（同人两框相距 0.014–0.03）仍然稳稳命中，而两名队友需要同时满足"贴得极近 + 至少两帧互斥"才会被误并，且误并会以减少候选数暴露出来。

合并结果：按时间序拼接两方的观测；同一时刻两条观测取置信度更高者；`first_*` 取最早观测；`hits` / `court_points` / `body_qualities` / 外观序列同步拼接。合并只发生在同一机位内部。

替代方案（未采用）：① 帧内先做 NMS——本案例两个框的 IoU 仅 0.15，常规 IoU-NMS 并不会合并它们；单纯调 IoU 阈值又会误伤真正贴近的两名球员。② 用外观特征直接聚簇——既有规格明确"单一低质量外观证据 MUST NOT 标记为确认"，且远景外观质量低，单独使用不可接受。③ 放宽"一帧吸收一个检测"到"一帧可吸收多个"——会让 `test_one_tracklet_cannot_absorb_two_people_in_one_frame` 断言的行为反转，风险更大。

### D3 分侧判据：复用正式管线语义，配置化以防漂移

新增 `BootstrapPreflightConfig.side_dead_zone_ft: float = 2.0` 与 `court_half_length_ft: float = 22.0`。判据与 `_BootstrapTracklet.inferred_side` 完全一致：对该候选全部有效投影点的 canonical y 取**中位数**；`|中位 y − 22| < 2.0` → 未知；否则 `y < 22` → A 端侧、`y > 22` → B 端侧。

- 用中位数而非单点：既有的 `_score_tracklet` 也用全轨迹统计，单点投影抖动不应改变侧向。
- 未知侧 **不参与配额约束**：可以被任一侧的剩余配额吸收。这样"缺标定 → 全部侧向未知"的素材仍按综合分给出 4 名候选，与今天行为一致，不会因为本次改动反而退化。
- 单一来源保护：预检刻意不 import `player_lock_manager`（保持纯逻辑边界），改为在契约测试里断言 `BootstrapPreflightConfig().side_dead_zone_ft == _BootstrapTracklet.SIDE_DEAD_ZONE_FT`，两处数值漂移会在测试里立刻暴露。

### D4 一侧不足时不跨侧补位

若某一侧的有效候选数少于配额，则保留该侧已有候选、不使用对侧候选补位，写出诊断 `bootstrap_preflight_side_quota_unfilled`（severity=warning，detail 含每侧 expected/actual 与 `match_format`），并由既有逻辑把状态置为 `insufficient_candidates`（候选总数 < 期望人数）。

理由：候选一旦被用户确认就会被冻结成 `AnalysisRosterSnapshot`，错误的第 4 名会静默污染 Team A/B 与所有依赖正式身份的指标；而确认页已经支持"未识别，待补全"与手工框选，少一名是可处理的状态，错一名是不可发现的错误。这与既有规格"不得为了凑满四人选入场外人员"以及 `court-aware-attention-player-selection` 的"不得用低分隔壁场候选补满四人"一致。

替代方案（未采用）：加 `allow_side_backfill` 配置默认关闭——不产生实际差异的死配置，等真有素材需要时再加。

### D5 可观测性

- `PlayerBootstrapCandidateEvidence` 新增可选字段 `side: str | None`（取值 `"end_a"` / `"end_b"` / `None`，`None` = 死区内或无投影）。字段可选、向后兼容，不升契约大版本。
- 诊断码新增 `bootstrap_preflight_side_quota_unfilled`；既有 `bootstrap_preflight_off_target_court`、`bootstrap_preflight_deterministic_order`、`bootstrap_preflight_budget_exhausted` 语义不变。
- 合并只在内部发生，不新增"被合并轨迹"的候选条目；被丢弃的重复轨迹通过合并后的 `hits` / 采样命中数体现。

### D6 顺带收紧的最小项

`min_bbox_width_px = 18` / `min_bbox_height_px = 48` 保持不动（本案例的重复框尺寸均远超门槛，不是成因），避免把不相关的阈值调整混进本次变更。

## Risks / Trade-offs

- [两名队友站位极近（< 0.08 归一化）且其中一人连续两帧被遮挡 → 可能误合并] → 合并半径收到 0.08、要求共享时刻也从未分离、外观明显不同时否决；误合并的直接后果是候选变少并被 `insufficient_candidates` 暴露，不会静默冒充正确身份。
- [标定漂移让同一名球员的投影落在中线两侧] → 用轨迹内 court_y 中位数 + 2ft 死区，死区内判未知且不受配额约束。
- [严格配额会把"1 近 + 3 远"的素材从 4 名降到 3 名] → 刻意的诚实降级；任务 4.x 用真实素材做前后对照，确认本次素材仍给出完整 2+2，并另造一个"一侧不足"的场景验证降级诊断。
- [既有预检测试把所有球员都放在同一侧 (`court_xy=(2+4i, 6.0)`)，严格配额会让它们从 4 名降到 2 名] → 这是行为变更的必要代价：任务 2.x 显式改写测试场景数据，给球员分配真实侧向，并新增"分侧不足"用例；不得为了让旧断言通过而放宽配额。
- [`BootstrapPreflightConfig` 新增字段改变 `signature()` → 进程内预检缓存全部失效] → 预期行为，无迁移动作；与本次无关的冷请求耗时问题不在范围内。
- [槽位编号改变会让历史截图/沟通里的"P1=近端白衣"不再对应] → 槽位编号本来就是"用户确认前的建议位"，确认页允许交换；本次把建议位改成有语义的分组，属于改进而非破坏。

## Migration Plan

1. 先改引擎（D1–D5）与配置默认值，再改测试数据与新增用例。
2. 无数据迁移：名册在创建任务时由用户确认后冻结，磁盘上不存"预检建议顺序"。
3. 回滚：还原 `player_bootstrap_preflight.py` + `rally_context.py` 的可选字段 + 测试即可，无持久化副作用。
4. 回归：`pytest` 预检与契约测试；用 `take ct_9997fa5aedf7` 的真实素材离线复现（只读，不写产物），确认 P1–P4 变为正确的 2+2、重复候选消失、`sampled_frame_count` 与诊断码符合预期。
