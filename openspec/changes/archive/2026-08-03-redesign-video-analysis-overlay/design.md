## Context

真实视频分析页目前由 `VideoAnalysisCard` 负责视频播放、检测框、RTMPose 骨架、球点和弹跳候选叠加，由 `CourtMinimap` 负责右上角球场小地图。小地图只接收 `PipelineTrackPoint[]`，没有接收球轨迹或弹跳候选；球轨迹则在视频 SVG 中按固定样本数量绘制，当前任务的 60 FPS 视频和 2 帧抽样会把可见尾迹压缩到约 0.6 秒。

后端已经提供稳定球员身份、球员球场投影、球轨迹的 `image_xy`/`court_xy`、置信度/插值标记以及弹跳候选的图像和球场坐标。当前真实任务还存在缺失帧、越界投影和低置信度候选，因此前端必须保留数据来源和不确定性，不能为了画面连续而虚构检测结果。

本 change 以交互式前端叠加层为主，不改变后端 artifact schema、球检测算法或可下载叠加视频生成链路。

## Goals / Non-Goals

**Goals:**

- 将小地图升级为与视频融合的半透明分析 HUD，并保持视频为主视觉。
- 在同一视频时间轴上同步展示球员移动轨迹、当前位置、方向、速度摘要、球轨迹和弹跳候选。
- 让轨迹按时间窗口、数据缺口、置信度和插值状态渲染，避免固定点数过短或跨缺口误连。
- 为人框、骨架、球点、球路和弹跳候选提供独立可见性控制。
- 复用现有 artifact API，保持 loading、unavailable、failed 和 no-candidates 状态可解释。
- 让窄屏、桌面和全屏模式下的地图、控件和状态信息不互相遮挡。

**Non-Goals:**

- 不从单摄二维坐标推导真实三维球速、过网高度或测量级飞行弧线。
- 不修改球检测、弹跳检测、球员跟踪、身份锁定或场地标定算法。
- 不新增后端 API，不改变现有 JSON artifact 的字段语义或坐标单位。
- 不在本 change 中同步重做后端生成的下载版 overlay video。
- 不新增 Three.js 或其他重量级可视化依赖；视频内 HUD 使用现有 React、SVG 和 CSS。

## Decisions

### 1. 使用前端 HUD 作为唯一交互展示层

`VideoAnalysisCard` 继续持有视频时间、播放、拖动、全屏和图层开关状态；`CourtMinimap` 负责纯 SVG 球场绘制。新增一个轻量的 HUD view-model/纯计算层，统一把球员、球、弹跳候选和当前时间转换为渲染段，避免在 JSX 中重复处理时间筛选和单位判断。

选择前端而不是先改后端 overlay video，是因为前端已经具备 `requestVideoFrameCallback` 同步机制和独立图层交互；当前真实任务的 overlay video URL 也可能为空。这样可以即时拖动查看、独立关闭图层，并保留后端数据的原始状态。

备选方案是仅改后端 `MinimapVisualizer` 和 `OverlayVideoWriter`。该方案适合下载成片，但无法提供独立开关、交互式状态和低延迟拖动，因此不作为本 change 的首选。

### 2. 小地图保留球场比例，默认聚焦正式球场

小地图使用标准球场几何建立内部坐标变换，保持 20×44 英尺的纵横比；正式球场采用主要视觉层，tracking bounds 只作为低透明的外扩区域或越界诊断层。地图容器使用稳定的宽高约束，避免视频尺寸变化导致球场拉伸或控件跳动。

选择“正式球场优先”是因为当前固定 tracking bounds 会使正式球场占比偏小，用户难以判断球员和球的位置。仍保留外扩区域是为了表达投影越界和边界诊断，不把越界数据静默裁剪成正常位置。

### 3. 轨迹按时间窗口和缺口分段

球员尾迹默认使用约 3 秒窗口，球尾迹默认使用约 1.2 秒窗口；最终窗口由 timestamp 过滤，而不是由固定样本数量决定。相邻点时间差超过配置阈值时拆分为不同 polyline，禁止跨缺失区画直线。轨迹点数量超过渲染上限时使用稳定的时间均匀降采样。

球员当前位置使用最近有效点；方向箭头和速度摘要使用最近一小段有效点计算。速度显示必须明确单位，并通过已有坐标单位转换；当单位 metadata 不可确认时显示“速度不可用”，而不是猜测单位。

### 4. 球路同时表达图像空间和球场平面

视频主画面上的球路使用 `image_xy` 绘制高对比渐隐尾迹，表达球在画面中的连续运动；小地图上的球路使用 `court_xy` 绘制平面投影，表达落点和横向线路。有效检测、插值点和低置信度点使用不同透明度或线型。

弹跳候选使用时间邻近的环形 marker，并在小地图中保留历史候选的弱化状态。当前 artifact 没有真实高度字段，因此界面文案使用“视觉估算球路”或“球场平面投影”，不得把平面线条命名为测量级三维弧线。

### 5. 图层开关采用独立状态

将人框、骨架、球点、球路、弹跳候选拆为独立布尔状态；旧的“球”控制保留兼容含义但不再同时隐藏所有球相关信息。控制区使用紧凑的图标加文字按钮，具备 `aria-pressed`、不可用状态和 tooltip/辅助标签。

独立状态可以让用户在球员移动复盘时隐藏骨架，或在球路复盘时隐藏人框，减少叠加层之间的视觉竞争。

### 6. 真实数据优先，缺失时降级而不回退到模拟数据

HUD 只消费真实 job 的传入 artifact。某个 artifact loading、failed、unavailable、no-candidates 或当前时间没有有效点时，只更新对应图层的状态提示；不得用 demo player、静态球点或虚构球路填充真实任务。

所有计算函数保持纯函数并接受空数组、非法坐标、空时间和未知单位，便于单元测试和错误边界处理。高频播放期间只更新当前时间和已 memoize 的渲染数据，不在每个视频帧触发全量排序或重复构建所有几何对象。

## Risks / Trade-offs

- [二维数据无法证明球的真实高度] → 同时展示图像空间球路和球场平面投影，并在 UI 中标明视觉估算；真实三维高度另立 change。
- [球检测存在缺失和插值] → 按时间缺口断线，插值段降透明或虚线，并显示当前球层状态和有效性摘要。
- [球员轨迹点数量较大] → 只在当前时间窗口内筛选，按每条轨迹设置上限并稳定降采样；避免每次播放更新扫描全视频。
- [现有任务可能缺少 coordinate unit metadata] → 速度计算先检查单位；无法确认时不显示数值速度，只保留方向和位置。
- [HUD 可能遮挡视频内容] → 提供紧凑模式、全屏适配和可移动/可隐藏的图层区域；地图尺寸使用响应式约束而非固定覆盖画面中心。
- [现有未提交改动与本 change 重叠] → 实现时只修改本 change 触及的组件和测试，先读取并保留用户已有修改，不做全文件回退。

## Migration Plan

1. 先增加纯计算层和新 HUD 的测试，再以兼容 props 的方式扩展 `CourtMinimap` 与 `VideoAnalysisCard`。
2. 在真实视频数据存在时启用新 HUD；没有 `pipelineTracks` 或球 artifact 时保留现有视频播放和清晰的 unavailable 状态。
3. 完成桌面、窄屏和全屏视觉检查后，再移除旧的小地图内部绘制路径；不修改后端 artifact 文件。
4. 如新 HUD 出现回归，可回滚前端组件变更，后端任务产物和旧 API 不受影响。

## Open Questions

- 速度摘要首版是否只显示球员速度，还是同时显示基于图像坐标的球速估算？默认只显示球员速度，避免把不稳定的像素速度误解为真实球速。
- 越界球员点是否默认可见？建议默认以低透明度保留，并提供“边界诊断”开关；正式球场内点保持主视觉。
- 是否需要把发球候选作为独立 HUD marker？建议首版沿用已有时间轴发球候选，只有当用户明确需要“发球起点 + 球路”联动时再加入地图层。
