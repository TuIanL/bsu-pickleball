## Context

当前前端使用自定义 `pushState` 路由。`AnalysisTasksPage` 的来源 tab 保存在组件 state 中，进入分析详情后页面重新挂载，`sourceFilter` 会回到 `upload`；多个页面又把返回目标硬编码为 `/analysis/tasks` 或 `/capture`，因此入口上下文无法恢复。

双摄向导由 `MultiViewAnalysisSetupPage` 管理四个本地步骤，A/B 标定由共享 `CourtCornerCalibrator` 完成。向导只有确认页提供了“上一步”，标定页的取消回调直接退出到 `/capture`。标定回调已经返回点位数据，但父页面目前只保存 calibration id，没有保存点位草稿。关键操作使用的 `primary-button` 与 `sport-button` 也没有在主应用样式中定义。

本 change 只涉及前端导航、向导状态和视觉样式，不改变分析 API、后端任务模型或算法执行逻辑。

## Goals / Non-Goals

**Goals:**

- 让任务列表来源 tab 和双摄录制 session 成为可恢复、可测试的导航上下文。
- 让任务详情、视觉结果、录制工作台和双摄向导根据来源返回到正确的业务页面。
- 让双摄四阶段流程具有明确的退出、上一步、下一步和提交操作。
- 返回前置标定步骤时保留已完成的点位草稿和 calibration id，允许用户修正后继续。
- 让向导内所有主要按钮使用有边框、有 hover、disabled 和 focus 状态的应用按钮样式。
- 为路由解析、上下文恢复、向导步骤和按钮状态补充回归测试。

**Non-Goals:**

- 不修改后端 API、数据库、分析任务创建契约或双摄同步算法。
- 不把浏览器原生历史回退完全替换成 `history.back()`；产品返回按钮仍使用明确的业务目标，避免直达页面或刷新后回退到应用外部。
- 不重做任务管理页面的视觉布局、任务分组算法或删除语义。
- 不允许用户跳过未完成的标定步骤；步骤条仍只允许按流程推进，返回用于修正已访问步骤。

## Decisions

### 1. 使用有限枚举的 URL 查询参数保存任务列表上下文

任务列表使用有限的 `source` 值：`upload`、`recorded`、`sync_recording`，双摄场景额外携带 `session`。典型地址为 `/analysis/tasks?source=sync_recording&session=<id>`。路由解析层负责校验枚举，非法值回退到 `upload`。

任务 tab 切换更新查询参数并使用 replace 历史语义，避免用户在任务页内切换 tab 后按浏览器后退要逐个穿过 tab。真正进入详情、向导或结果页仍使用 push 历史语义。

备选方案是只使用 `sessionStorage`。它能覆盖同一标签页的返回，但无法表达可复制的页面上下文，也无法稳定支持刷新、深链接和多个任务页面，因此不采用纯 sessionStorage 方案。现有的分析模式筛选可以继续使用 sessionStorage，但来源 tab 以 URL 为权威来源。

### 2. 用受控的任务列表上下文生成返回地址

新增前端内部的任务列表上下文类型和路径生成 helper，所有从任务管理进入的详情/结果/工作台链接携带有限来源信息。返回目标由以下优先级决定：显式 URL 上下文，其次由任务类型推断（multiview Parent → `sync_recording`），最后回退到上传任务。

不传递任意可执行的 `returnTo` 字符串，只传递有限枚举和 session id，避免页面之间形成难以维护的任意跳转协议。双摄录制卡片还携带 session id，使返回后可以恢复双摄 tab，并为后续定位原卡片预留稳定锚点。

### 3. 双摄向导采用“业务退出 + 步骤回退”两层导航

向导顶部提供固定的“返回双摄任务”业务退出入口，目标为带 `source=sync_recording` 和当前 session 的任务列表。步骤区域提供：

```text
步骤 0：退出 | 下一步
步骤 1：上一步 | 完成 A 标定后进入下一步
步骤 2：上一步 | 完成 B 标定后进入确认
步骤 3：上一步 | 开始双摄协同分析
```

标定组件的 `onCancel` 在步骤 1/2 中只负责回退一步，不再承担离开整个向导的职责。顶部退出入口在所有步骤保持可用。确认页失败时保留 calibration id；同步素材错误回到步骤 0，提交网络错误则停留在确认页并允许重试。

### 4. 保存标定草稿并支持回到前置步骤

父向导保存 A/B 各自的点位草稿和 calibration id。`CourtCornerCalibrator` 增加可选的初始点位输入，在组件重新挂载时恢复草稿；视频 id 改变时清理不匹配的草稿。用户返回某一步后可以重新点选四角，新的完成回调覆盖旧 calibration id 和点位。

不把整个向导状态写入后端或新增数据库字段。刷新页面仍重新执行素材加载并从步骤 0 开始，这是当前向导的本地临时流程边界；本 change 解决的是页面内返回造成的状态丢失。

### 5. 统一使用现有按钮样式并审计受影响 class

向导中的主要提交操作使用 `green-button`，返回、上一步和辅助操作使用 `quiet-button`。对受影响路径中的 `primary-button`、`sport-button` 使用点进行清理，并补充测试或静态检查，防止新页面继续引用未定义 class。除非其他现有组件确实依赖其语义，否则不新增另一套按钮设计系统。

### 6. 用页面级和路由级测试锁定行为

- 路由测试覆盖任务列表 query 参数的解析、非法值回退和 session 保留。
- 任务页测试覆盖切换双摄 tab、从双摄卡片进入详情以及返回地址携带双摄上下文。
- 向导测试覆盖每一步的返回目标、上一步不离开页面、标定草稿恢复、提交失败重试和按钮 disabled 状态。
- 对分析详情、视觉分析、报告和录制工作台至少覆盖双摄来源返回路径，保留已有单摄/上传回退行为。

## Risks / Trade-offs

- [旧链接没有来源 query 参数] → 按任务类型和现有字段推断 multiview Parent；无法推断时回退上传任务，确保旧书签仍可打开。
- [URL query 与组件 state 在异步加载期间短暂不一致] → 页面初始化时只从解析后的 query 读取来源，数据加载只更新列表内容，不重置来源 state；tab 更新统一走同一 helper。
- [返回到原 session 但列表顺序变化] → 使用 session id 作为稳定上下文和可选 DOM 锚点，不依赖列表索引；找不到 session 时仍展示双摄 tab。
- [回到标定步骤后重新提交产生旧 calibration 产物] → 新 calibration id 直接替换父状态，旧产物保持现有后端共享资源清理契约，不在本 change 扩展删除行为。
- [按钮 class 清理影响其他未覆盖页面] → 先全局检索 class 使用点，再按现有语义替换或补充兼容样式；验证 TypeScript、lint 和相关页面测试。

## Migration Plan

1. 先增加导航上下文类型、query 解析和任务列表路径 helper，保持无 query 地址兼容。
2. 接入任务列表 tab、双摄卡片、详情/结果/工作台返回路径。
3. 改造双摄向导和标定组件的步骤回退、草稿恢复及按钮样式。
4. 增加并运行路由、任务列表、向导和结果页回归测试，再运行前端 build/lint。
5. 若出现导航回归，可回退前端 change；不会影响后端任务、录制文件和分析产物。

## Open Questions

- 返回双摄任务列表后是否必须自动滚动并高亮原来的录制卡片？本设计先保留 `session` 上下文和稳定定位能力，具体高亮动画可在实现时按现有列表结构决定。
- 是否要把来源 query 的参数名暴露为公开 URL 契约？当前仅作为前端内部导航协议使用，暂不承诺第三方兼容。
