## Context

分析任务管理页（`src/pages/AnalysisTasksPage.tsx`）的「上传视频任务」tab 已具备完整的选择/删除机制：

- 工具栏：全选复选框、「已选 N 个可删除历史任务」计数、排序、清空选择、批量删除、「清除失败/取消」。
- 每张任务卡片右上角有「选择」复选框，仅对非运行中（可删除）任务开放。
- 选择集保存在单一 `selectedJobIds` 状态；批量删除调用 `deleteAnalysisJobs`（后端 `POST /api/analysis/jobs/delete`，本地样例任务经 localStorage 兜底删除）。
- 任务带 `analysisMode`（`"demo" | "real" | "limited"`），`analysisModeLabel` 已提供中文标签映射。

现状缺口：无法按分析模式（样例任务 / 有限真实分析 / 真实视频分析）一键圈定同类全部任务后删除。用户需逐卡勾选或全选后手动排除，效率低且易误选。

已确认的产品决策：功能仅作用于「上传视频任务」tab；模式勾选只选中该类**可删除**（非运行中）任务；取消勾选同步移除该类任务；删除仍复用现有「批量删除」按钮。

## Goals / Non-Goals

**Goals:**
- 在工具栏提供「按类型选择」入口，弹出小选项卡，三个模式多选并显示各自可删任务数。
- 模式勾选/取消与现有选择集实时联动，全选、单卡勾选、模式选择共用同一 `selectedJobIds` 状态，行为一致。
- 用户手动调整单卡后，模式复选框能正确表示未选/半选/全选三种状态。
- 删除复用现有批量删除按钮、确认与反馈流程，后端零改动。

**Non-Goals:**
- 不改动后端 API 与数据结构（`analysisMode` 字段已存在）。
- 不在「录制视频任务」「双摄录制」tab 增加模式选择（无分析模式概念）。
- 不做基于模式的列表筛选/过滤（只做选择，不做视图切换）。
- 不在弹层内提供删除按钮。

## Decisions

### D1: 模式选择是"选择集的批量快捷操作"，不引入第二套选择状态
模式勾选直接增删现有 `selectedJobIds`，而不是维护独立的"模式→任务"映射再合并。
- 理由：单一状态源避免全选/单选/模式选择/删除之间出现不一致；删除、计数、清空选择、反馈全部自动复用现有逻辑。
- 备选：维护独立的模式选择状态，提交删除时合并——需要处理两种状态的同步与去重，复杂度高，无收益。

### D2: 模式勾选只作用于可删除任务（`eligibleJobIds`）
与现有"全选"仅覆盖可删除历史任务的语义一致；运行中任务不因模式勾选被选中，避免"勾选了却删不掉"。
- 模式计数 = 该模式下 `eligibleJobIds` 的任务数；模式勾选态基于可删任务在 `selectedJobIds` 中的覆盖情况计算。

### D3: 勾选态三值计算（未选 / 半选 / 全选）
模式 `m` 的勾选态由 `eligible(m) ∩ selectedJobIds` 决定：
- 空集 → 未选；真子集 → 半选（`indeterminate`）；全集 → 全选。
- 勾选动作：把 `eligible(m)` 全部加入 `selectedJobIds`；取消动作：把 `eligible(m)` 全部移除。
- 用户手动勾/取消某张卡片后，重算各模式勾选态，半选态自然浮现。
- 理由：双向一致、实现直观；`<input type="checkbox">` 的 `indeterminate` 属性即可表达半选。

### D4: 弹层用轻量 popover，不复用 Modal
新增小组件（如 `src/components/platform/ModeBatchSelectPopover.tsx` 或就地实现）：按钮 + 绝对定位面板，`useRef` + 全局 `mousedown` 点击外部关闭，支持 `Escape` 关闭。
- 理由：Modal 太重（遮罩 + 居中），不适合工具栏快捷弹层；项目暂无 popover 组件，就地实现最贴合现有代码风格。
- 备选：引入 UI 库下拉组件——引入新依赖，超出本 change 范围。

### D5: 删除入口复用现有「批量删除」按钮
弹层只负责选择；用户选中后关闭弹层，点击工具栏「批量删除」走既有确认与反馈流程。
- 理由：与用户确认的决策一致，改动面最小；删除逻辑（含 demo 任务 localStorage 兜底）零改动。

### D6: 空态与禁用
上传任务列表为空、或某模式下无可删除任务时，对应模式复选框禁用（计数为 0）；整个列表无可删除任务时「按类型选择」按钮保持可用但选项不可勾选，或按钮禁用。
- 理由：避免无效操作，同时保持入口一致性。

## Risks / Trade-offs

- [半选态与手动选择的冲突] → 勾选态一律由「`eligible(m)` 在 `selectedJobIds` 中的覆盖」实时重算，勾选/取消动作以覆盖集为准，用户手动增删后状态自动收敛，不会出现"复选框状态与选择集矛盾"。
- [点击外部关闭的边界情况（面板内滚动、按钮自身点击）] → 用 `mousedown` + `ref.contains(e.target)` 判断，按钮点击不触发关闭，面板内点击不关闭；`Escape` 兜底关闭。
- [批量删除部分失败（运行中/缺失任务）] → 现有 `deleteAnalysisJobs` 返回逐任务结果，前端已有反馈汇总；模式选择只选可删任务，进一步降低失败面。
- [弹层遮挡列表操作] → 面板尺寸受限于工具栏区域，选项固定三项（含计数），不随任务数增长，遮挡风险低。

## Migration Plan

纯前端改动，无数据迁移。发布后「上传视频任务」tab 工具栏即出现「按类型选择」入口；回滚只需移除入口与联动逻辑，不影响既有选择/删除行为。
