## Context

普通片段页已加载当前正式切分 run 的 active algorithm Rally 区间，并在点击某个回合后通过有界片段播放和自然结束回调实现自动续播。普通播放按钮仍直接调用媒体播放，因此从 0:00 或非比赛时间位置播放会绕过跳过策略。现有 `auto-skip-non-play-playback` 规格也明确记录了这个旧行为，需要同步更新。

后端已有片段列表与正式切分摘要 API，无需为播放跳转新增接口。片段列表路由从另一个路由模块导入私有 `_seg_dict`；正式切分发布服务与摘要路由也分别维护成功状态集合。

## Goals / Non-Goals

**Goals:**

- 自动跳过开启时，使普通播放入口按播放头所在位置选择比赛回合并连续跳过回合间隙。
- 保留开关关闭、手动定位、自然播放结束、末段停止及边界复核模式的既有语义。
- 降低片段 API 路由间的私有函数耦合，并复用正式切分可用状态定义。
- 保持所有后端 API 字段和语义不变。

**Non-Goals:**

- 不把播放跳转策略移到后端，不新增 API 或播放器服务端状态。
- 不更改自动回合识别算法、active run 选择规则、回合边界口径或数据库结构。
- 不重写正式切分工件的复用、持久化、失败审计流程。
- 不改变边界复核隔离模式的双机位同步播放。

## Decisions

### 1. 由已加载的回合区间在客户端解析播放起点

播放请求到达普通片段页时，以当前播放头和当前正式 run 的 active algorithm Rally 区间做解析。区间按左闭右开 `[start, end)` 判定：播放头位于回合内时从当前位置续播到该回合终点；播放头在首回合前或回合间隙时，跳到起点不早于播放头的首个回合；播放头位于末回合之后时保持暂停，不播放尾部非比赛时间。自然播完当前窗口后沿用现有“寻找起点不早于窗口结束时间的下一回合”规则。

选择客户端解析是因为片段页已经取得完整区间数据，播放位置与开关状态也由客户端持有。新增后端查询会增加往返请求，并把纯播放体验状态引入服务端。

自动跳过关闭时，播放请求继续使用现有自由播放语义。点击右侧回合仍从该回合起点播放；拖动进度条仍允许停在任意位置，拖动本身不立即跳转。仅用户随后发起播放时，开启状态才对当前播放头应用上述解析。边界复核模式继续使用原有同步播放处理。

备选方案是让 `SegmentVideoPlayer` 自行读取回合区间并选择下一段；不采用该方式，因为区间归属、当前正式 run 和自动跳过开关都由片段页掌握，放入播放器会耦合通用媒体控件与领域规则。

### 2. 后端复用共享片段序列化逻辑与切分状态集合

将片段 ORM 对象到 API 字典的映射从 `routes_segment_editing.py` 私有 helper 移到共享后端模块，由片段编辑与片段列表路由共同调用。将“已发布/可用”的正式切分状态集合定义为单一来源，供切分复用逻辑和产品摘要路由共用；摘要路由在本地计算一次状态判定并复用该结果。

这两项调整只整理现有职责边界。序列化字段、兼容缺省值、摘要选择的运行规则、HTTP 状态及数据库写入均保持不变。

备选方案是让 `routes_coding_actions.py` 继续导入另一路由的私有函数，改动量较小但保留模块间反向耦合；也可以重写正式切分持久化路径，但该路径还承担失败重试保护和不可变工件复用，超出本次清理范围。

## Risks / Trade-offs

- [从间隙发起播放会改变现有规格行为] → 更新自动跳过规格，并覆盖首回合前、回合间隙、回合内部、末回合之后及关闭开关的行为。
- [播放器组件缺少普通模式的页面级播放请求通知] → 复用现有播放切换回调通道，使点击与键盘播放入口进入同一解析路径；暂停仍直接暂停媒体。
- [抽取序列化器或状态集合可能意外改变 API 响应] → 保留原字段映射和枚举值，使用既有路由测试验证响应兼容。
- [复核模式误入新的跳过路径] → 只在普通片段页接入解析；复核模式继续显式使用现有同步处理器。

## Migration Plan

无需数据库迁移或部署顺序调整。先完成客户端播放入口与回合区间解析，再抽取并替换后端共享 helper；保留原 API 路径和响应格式即可回滚，无需数据修复。

## Open Questions

无。播放头在回合内部、间隙及末回合之后的行为已确认。
