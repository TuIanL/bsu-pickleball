## Context

当前项目是前后端分离的本地优先应用：React/Vite 前端通过 `analysisClient` 调用 FastAPI，后端将分析任务和 artifact 持久化到 SQLite 与本地文件系统。最近多次功能变更同时触及路由、录制分析桥接、模型自动发现和视频可视化，导致代码、测试、OpenSpec 与运行数据出现不同步。

已确认的基线问题包括：TypeScript 构建失败、前端测试失败、Lint 大量失败、后端 11 个测试失败、默认 SQLite 存在历史活跃录制记录，以及 demo fallback 可能掩盖真实 API 故障。本变更需要跨越前端类型层、API schema、pipeline artifact、测试 fixture 和文档，但不新增视觉算法。

## Goals / Non-Goals

**Goals:**

- 让前端 `build`、前端测试、前端 Lint 和后端 pytest 都达到明确且可重复的通过基线。
- 建立前后端共享的分析任务归属字段契约，支持录制 session 与 camera slot 的读取、筛选和展示。
- 让 artifact 状态能区分“未启用/跳过”“不可用”“失败”和“已生成”，并保持历史任务可读取。
- 统一任务列表规范路由，同时保留旧链接兼容能力。
- 让测试使用临时数据库/临时文件并显式控制模型发现，避免依赖本地运行数据和仓库模型资产。
- 让真实 API 请求失败在 UI 中可见，不再无提示地伪造已完成 demo 任务。

**Non-Goals:**

- 不更换 YOLO、RTMPose、球检测或球员身份算法。
- 不删除生产环境已有的历史任务、录制文件或 SQLite 数据；数据清理只针对测试隔离和显式的迁移工具。
- 不在本变更中设计新的认证、部署、分布式队列或云存储方案。
- 不把所有现有 Lint 警告简单关闭；只允许对有明确理由的第三方/兼容边界保留例外。

## Decisions

### 1. 以类型契约为入口修复前端构建

补齐 `AnalysisUploadMetadata` 和 `AnalysisJobSummary` 中的录制归属字段，并由 API client 负责兼容 snake_case 后端字段与 camelCase 摘要字段。路由继续使用判别联合，`routeMeta` 保持精确字面量，通过表驱动测试锁定 `/capture`、`/capture/:id/analyze`、`/tasks` 和 `/analysis/tasks` 的行为。

选择共享类型契约而不是在页面内使用类型断言，因为当前构建错误正是由页面绕过共享契约造成的；大范围 `as any` 只能隐藏后端字段继续漂移。

### 2. 规范化任务路由，保留兼容别名

将 `/analysis/tasks` 作为规范分析任务列表入口，`/tasks` 继续解析到同一个 `AnalysisTasksPage`，并在内部导航逐步使用规范入口。这样可以满足侧边栏和新规格，同时不破坏已归档规格、浏览器书签和旧页面跳转。

选择兼容别名而不是立即删除 `/tasks`，因为项目已有历史 OpenSpec、README 和代码路径引用它，立即删除会扩大迁移范围并制造无意义的 404。

### 3. 用显式状态表统一 artifact 语义

pipeline 在所有可选 artifact 上输出稳定的 `status` 与 `detail`：`available` 表示文件可读取，`skipped` 表示配置或前置条件主动跳过，`unavailable` 表示能力或模型不可用，`failed` 表示执行异常。文件不存在时仍可保留状态描述，但 artifact endpoint 返回 404，不暴露绝对路径。

选择状态表而不是让 `path != null` 推导状态，因为“不可用但有诊断信息”和“跳过但没有文件”都是前端需要展示的真实产品状态。

### 4. 测试环境与运行环境完全隔离

后端测试统一使用 `tmp_path` 下的数据库、存储目录和模型目录；需要测试模型自动发现时显式创建假模型文件。录制生命周期测试的 fake session factory 必须返回可控的空查询结果，不能让未配置的 `MagicMock` 被解释成存在活跃记录。默认本地 `backend/data/app.sqlite3` 不作为测试 fixture。

选择测试隔离而不是清空仓库数据库，因为清空运行数据是破坏性操作，也会掩盖生产环境对孤儿 CaptureTake 的恢复问题。

### 5. 真实 API 失败优先可见

`analysisClient` 只在明确的 demo 路径或没有真实输入且产品允许 fallback 时创建本地 demo job。网络错误、HTTP 4xx/5xx 和真实视频任务失败必须返回可识别错误，由页面展示错误/不可用状态；localStorage 仅保存已明确创建的本地 demo 任务，不作为真实任务成功的替代品。

选择显式失败而不是全局 fallback，因为当前行为会把后端不可用误报为“分析完成”，比页面显示错误更难排查，也会污染任务历史。

## Risks / Trade-offs

- [兼容风险] 规范化任务路由可能改变部分旧页面的 active sidebar 状态 → 保留 `/tasks` 别名，并为两个入口补充等价路由测试。
- [数据兼容风险] 历史任务缺少录制字段或 artifact 状态 → 所有新增字段保持可选，读取层提供 `undefined/null` 兼容分支，不修改历史 JSON。
- [模型环境差异] 不同机器的模型资产目录不同 → 测试显式指定模型目录，生产配置继续允许自动发现，但把发现结果和显式开关记录到诊断信息。
- [Lint 工作量] React 19 hooks 规则会暴露旧 effect 模式 → 分批按模块修复，必要时用行为测试保护异步加载和时钟更新，禁止一次性关闭整组规则。
- [运行数据遗留] 本地旧 SQLite 仍可能显示孤儿录制 → 通过启动恢复/强制终止路径处理，并在文档中明确测试数据库与运行数据库的区别；本变更不自动删除用户数据。

## Migration Plan

1. 先落地共享类型、路由和 artifact 状态契约，并补充失败回归测试。
2. 将后端测试迁移到临时数据库/存储目录，验证不读取仓库内默认 SQLite 和模型文件。
3. 收紧前端 fallback，完成构建、测试和 Lint 基线。
4. 同步 README、OpenSpec 与 API 路径，运行全量验证命令。
5. 若上线后发现兼容问题，保留 `/tasks` 别名和可选字段，不需要回滚历史数据；仅回滚 fallback 行为或新状态适配器即可。

## Open Questions

- 是否在后续独立变更中提供面向用户的“清理孤儿录制”管理界面；本变更只保证现有恢复/强制终止路径可测试。
- Lint 是否要求测试文件也达到零 `any`，还是允许对测试 double 使用局部、带注释的类型窄化；实现阶段需结合规则数量决定，但不能关闭全局规则。
