## Context

React 应用由 `App` 和 `AppShell` 统一承载路由；landing 有顶部栏，standard/capture 只有固定侧边栏。`src/index.css` 定义部分 `--capture-*` 变量，但大量页面仍使用 Tailwind 默认色和任意值；报告区还有 `.pb-vision-theme`，图表配置在 JavaScript 中指定颜色。现有 `localized-bright-ui` 规范把亮色写成全局唯一主题，本变更需将其收敛为默认亮色模式。

## Goals / Non-Goals

**Goals:**

- 首次访问保持现有亮色外观；用户手动切换后在路由切换和刷新后维持选择。
- 暗色模式以近黑色页面底和分层深色表面为基础，统一界面语义色并保持文字、状态和焦点可读。
- 在 landing 与 standard/capture 两种壳布局中提供位置稳定、键盘可用的切换入口。
- 让报告、图表的背景、轴线、标签、图例和提示框适配主题，同时保持数据颜色含义。

**Non-Goals:**

- 不增加“跟随系统”第三种模式，也不以系统偏好改变首次访问的默认亮色。
- 不重设计页面结构、业务流程、数据配色语义或视频画面内容。
- 不将无引用的 `src/styles/app.css` 重新接入应用。

## Decisions

### 主题状态与首帧

使用 `html[data-theme="light|dark"]` 作为唯一 DOM 主题标记；专用 `localStorage` 键仅接受 `light`、`dark` 两个值。`index.html` 的极小启动脚本在应用样式和 React 首次绘制前读取该值，缺失、无效或读取失败时设为 `light`。React 从相同标记初始化状态，点击后同步更新 DOM、存储和按钮状态；跨标签页 `storage` 事件同步，存储不可用时至少保证本页切换有效。设置 `color-scheme` 以匹配原生表单控件。选择该方案是为了避免暗色用户刷新时短暂闪出亮色；仅在 React `useEffect` 中恢复主题会太晚。

### 配色结构与迁移边界

保留当前亮色 `--capture-*` 值作为基准，新增缺少的页面底、表面、前景、边框、阴影、交互和浮层等语义变量，在 `[data-theme="dark"]` 下提供近黑色的对应值。`.pb-vision-theme` 的界面变量改为引用全局语义变量，保留六维度和热力图等数据语义变量。逐页将“界面色”硬编码迁到变量或显式主题变体；不通过全局 `filter`、反色或宽泛的 `bg-white` 覆盖规则改变图片、视频和数据标记。亮色变量值应与原解析颜色一致，并以关键页面截图检查回归。

Tailwind v4 的手动暗色变体在 `src/index.css` 声明 `@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));`。现有 `tailwind.config.ts` 未在 CSS 中用 `@config` 引入，因此主题能力不依赖该文件中的配置。组件中优先使用语义变量；少量独立样式使用显式 `dark:` 类。

### 切换入口

由 `AppShell` 提供共享按钮：landing 放在现有顶栏右侧；standard/capture 放在主区域右上角的壳级位置，并为可能相撞的页面标题操作区留出空间，不新增整条工作区顶栏。按钮使用 Lucide 月亮／太阳图标、明确的中文 `aria-label`／`title`、可见焦点环和足够的点击区域；图标表示点击后将切换到的模式。两个布局共享同一主题状态。

### 图表与特殊表面

ECharts 配置中的画布、网格、轴线、标签、图例和 tooltip 属于界面色，应从主题调色值生成并在切换时更新 option；Three.js 球场材质、canvas/SVG overlay 只调整充当界面背景或辅助线的部分。玩家、球队、热力图、状态、录制及告警色按语义保留，并在两种背景上校验可读性。弹窗、抽屉、输入框、空态和 hover/disabled/focus 态纳入逐页检查。

## Risks / Trade-offs

- [硬编码颜色分散，暗色出现遗漏] → 按壳、核心流程、报告/图表分批迁移，结合搜索清单和页面巡检覆盖。
- [亮色 token 化产生视觉漂移] → 保留原有计算色值；对首页、比赛库、采集、分析和报告进行亮色截图回归。
- [壳级按钮遮挡页面右上角操作] → 在相关页面标题区预留按钮空间，并检查窄屏、弹窗和滚动状态。
- [图表切换后保留旧色] → 将主题作为生成图表 option 的输入，并验证切换后重绘。
- [存储受限或无效数据] → 读取/写入容错，回退亮色或保持当前会话状态。

## Migration Plan

先建立主题状态与语义变量，再迁移界面色，随后覆盖报告和图表，最后执行亮/暗页面巡检与构建验证。无需数据迁移；回滚时移除新增主题逻辑与暗色规则即可，既有亮色值保持原样。

## Open Questions

无阻塞问题。实施中若个别图表的数据颜色在深色背景下对比不足，按该图表语义单独调整亮度与辅助描边。
