## Why

当前页面的浅色界面由全局 `--capture-*` 变量、Tailwind 默认色和分散的硬编码颜色共同构成。仅替换少量变量无法得到一致、可读的暗色界面；需要先收敛页面背景、卡片、文字、边框和阴影等界面语义色，再提供跨页面持久化的主题切换。

## What Changes

- 增加亮色与暗色两种手动切换的界面主题；首次访问默认亮色，已有选择在刷新和路由切换后保持。
- 在页面右上角提供月亮／太阳图标切换按钮，覆盖首页及工作区布局，并提供清晰的可访问名称和焦点状态。
- 将应用外壳和主要页面的背景、卡片、文字、边框、阴影、表单与浮层收敛到界面语义色；亮色下保持现有视觉结果，暗色以黑色为基调并维持层级、对比度和自然过渡。
- 对报告、图表和可视化容器中的界面色作相应适配；球队、热力图、录制和状态等数据语义色保留其含义，只在可读性不足时调整呈现。
- 更新现有“亮色主导视觉”规范，使其明确适用于亮色模式，并补充暗色模式要求。

## Capabilities

### New Capabilities

- `persistent-ui-theme`: 主题初始化、切换入口、状态持久化、跨布局一致性和暗色可读性。

### Modified Capabilities

- `localized-bright-ui`: 将既有亮色视觉要求限定为亮色模式，并要求亮色模式在语义色迁移后保持原有外观。

## Impact

涉及 `src/index.css` 的全局设计变量、`App`／`AppShell` 主题状态与入口、使用硬编码界面色的页面和组件、报告作用域样式，以及需随主题更新的图表配置。无需新增后端 API 或第三方运行时依赖；不改变业务数据和导航语义。
