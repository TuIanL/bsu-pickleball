# Design: 提升球检测与球路识别精度

## Context

当前球路链路包含候选检测、单视角跟踪、轨迹清洗、双摄关联/三角测量、混合段构建和前端 overlay 多个阶段，但各阶段对“这个点是否仍然可能是球”的判断并不统一。通用 `tennis-ball.pt` 权重可能把场边设备、广告和网后物体当作球；单视角跟踪在丢失后还可能锁定错误候选；轨迹清洗按采样点数量而不是实际秒数插值，导致长缺口被连接成貌似连续的球路。双摄链路目前也可能把低质量配对交给后续重建，前端则未始终按段级质量等级过滤默认 overlay。

本 change 只设计并实现质量约束、审计字段和展示资格的统一契约。历史 raw、cleaned、reconstructed artifact 保持只读兼容，不回写已有任务。

## Goals / Non-Goals

**Goals:**

- 以精度优先建立分层球候选质量门，降低场外物体误检和错误锁定。
- 用实际时间表达轨迹连续性、速度、加速度、缺口和插值上限。
- 让球场空间、运动连续性和双摄几何证据共同决定测量与展示资格。
- 让 `detected`、`interpolated`、`model_predicted`、断点和拒绝原因可审计、可复现。
- 让低质量单视角/视觉弧只在调试路径可见，默认页面不把不确定结果当成权威球路。
- 保持旧版本 artifact 的兼容读取，并为后续匹克球专用模型保留 detector adapter 边界。

**Non-Goals:**

- 本 change 不重新训练或替换球检测模型，不承诺一次性解决模型召回率问题。
- 不把单摄像头结果包装成真实 3D 测量，也不引入新的比赛判罚逻辑。
- 不重写历史任务的不可变 artifact，不改变球员分析、姿态分析或视频解码流程。
- 不在本 change 内完成完整的人工标注平台；只提供可用于离线评估的诊断和 fixture 接口。
- 不以物理模拟器替代视觉证据，物理约束只用于拒绝明显不合理候选和轨迹跳变。

## Decisions

### 1. 在检测、跟踪、重建和展示之间建立统一的质量门契约

新增后端质量门模块，接收候选框、时间戳、相机/球场几何和当前 track state，输出 `accepted`、`rejected` 或 `diagnostic_only`，并携带结构化 reason codes。各阶段可以有不同阈值，但不得绕过统一的发布语义。阈值进入任务配置快照，避免同一任务在重放时使用隐含的运行时默认值。

### 2. 使用投影球场空间棱柱，而不是只用地面四边形

对于有标定的视角，把标准球场的二维范围向外扩展为可配置的 3D court-space prism，再投影到图像空间。这样可以允许空中的球因高度产生合理的投影偏移，同时拒绝场外物体。没有可靠标定时使用带明确降级标记的宽松图像 ROI；降级 ROI 只能降低测量资格，不能自动提升为权威证据。

候选框还要经过置信度、面积比例、宽高比、尺度变化和静态区域黑名单等检查。尺寸阈值按图像位置或估计深度自适应，避免用单一像素阈值同时约束近处和远处的球。

### 3. 采用带确认和重捕获保护的时间状态机

候选首次出现时进入 `tentative`，必须在短时间窗口内满足 N-of-M 观测和运动门控后才能进入 `locked`。`locked` 丢失、重置或发生大跳变后进入 `lost`/`searching`；重新捕获使用更严格的空间、尺度和速度门，不能因为一个高置信度框立即接管旧轨迹。未经确认的候选只写入诊断，不进入正式球路和默认 overlay。

### 4. 所有运动和插值约束使用秒级时间

跟踪与清洗同时保留 frame index 和 timestamp，但速度、方向变化、加速度和缺口上限使用 `timestamp_sec` 计算。插值仅允许跨越配置的最大秒数，并且不得跨越显式 `lost`、`searching`、reset、异常跳变或事件边界；超出上限时关闭当前段，后续候选从新段开始。输出保留每个样本的 provenance 和断点原因。

### 5. 双摄关联需要硬门、质量排序和歧义余量

双摄候选配对同时检查时间一致性、重投影残差、三角测量角度/几何质量、3D 球场棱柱范围、相邻时刻轨迹连续性和候选分数歧义余量。只有通过硬门且相对次优配对有足够 margin 的 pair 才能成为权威双摄观测；低分或歧义 pair 可以进入 diagnostic，但不得驱动 anchor、三角测量或默认展示。

### 6. 将展示资格作为产物字段，而不是由前端自行猜测

每个 segment 输出观测覆盖、插值/预测比例、质量门摘要、断点信息、`display_level` 和 `display_eligible`。前端 adapter 只消费这些字段：默认渲染 `display_eligible=true` 的段，调试模式才显示 diagnostic-only 或低质量视觉弧。这样可以避免前端重新解释置信度或把低质量 segment 当作可展示结果。

### 7. 采用可回放的离线验收集

测试同时覆盖真实双摄样例、场边静态物体误检、遮挡后重捕获、长丢失、网前高速球和跨视角歧义配对。验收重点使用误检点精度、错误球路秒数、长缺口跨越率、断点正确率、双摄配对 precision 和默认展示合格率；召回率下降必须与误检下降一起记录，不能只看轨迹数量。

## Risks / Trade-offs

- 精度优先会牺牲部分高速球、遮挡球和画面边缘球的召回，需要用 `diagnostic_only` 和离线统计区分“未检测到”与“被质量门拒绝”。
- 球在空中时可能投影到球场边界外，棱柱投影必须足够宽；过宽会重新引入场边物体，需通过样例回放校准。
- N-of-M 确认和严格重捕获会增加轨迹端点延迟，端点应通过 provenance 表达，而不是用长插值补齐。
- 双摄严格配对可能减少 3D 覆盖，系统应允许合格的降级视觉段存在，但默认展示资格必须保持清晰。
- 旧 artifact 缺少新字段时只能按兼容规则降级读取，不应伪造新的质量分数或诊断结论。
- 阈值过多会增加配置和调试成本，因此首版使用集中配置、reason code 和配置快照，而不是把阈值散落在前端或各个 runner 中。

## Migration Plan

1. 先定义质量字段、reason code、display eligibility 和配置快照 schema，加入候选、跟踪、插值、关联与产物的单元测试/fixture。
2. 在单视角 tracker 和 cleaner 接入质量门，默认启用时间感知缺口与断点语义；保留诊断开关以便比较旧/新结果。
3. 在 joint runner 接入双摄 pair 硬门、质量排序和歧义诊断，确保低质量 pair 不再成为权威 anchor。
4. 更新混合段构建、artifact writer 和前端 adapter，使默认 overlay 遵守 `display_eligible` 与 `display_level`。
5. 使用真实样例和回放集验收；若某类视频召回下降超出可接受范围，通过配置版本回退阈值，不回写历史 artifact。新任务记录生效的配置版本，便于复现。

## Open Questions

- 首版 N-of-M、最大缺口秒数、速度/加速度阈值应由哪一批人工抽样标注确定？
- 是否需要在产品 UI 暴露“调试/原始检测模式”，还是仅通过开发配置开启？
- 单摄 `single_view_visual_arc` 的最低观测覆盖和默认展示阈值，是否需要按视频视角分档？
- 后续匹克球专用模型的训练数据和 hard-negative mining 是否单独建立 change，避免与规则质量门混合验收？
