## Context

当前球路页面消费 `reconstructed_ball_trajectory.v4`，前端不再自行分段或生成高度，而是把 artifact 的 `estimated_height_ft` 直接映射到 Three.js 场景的垂直轴。真实验收任务中已经出现两类不一致：

- 双摄 B-spline 优化器虽然包含 `z >= 0` 惩罚，但控制点没有非负硬边界，负高度样本仍可能以 `PARTIAL_3D` 进入混合 artifact，并被前端正式绘制。
- 事件锚定 2.5D 高度模型在只有终点锚点时将未知起点高度替换为已知终点高度，导致整段恒高；击球事件又全部使用同一个全局接触高度先验，无法表达不同击球情境的差异。

本变更涉及 3D 优化、2.5D 事件重建、混合 artifact 发布、前端适配和 WebGL 绘制。核心约束是：修复不能把球检测或标定误差伪装成正确轨迹，也不能通过把所有场外点吸附回标准球场来掩盖上游问题。

## Goals / Non-Goals

**Goals:**

- 从优化和发布边界阻止负高度 3D 曲线进入正式展示。
- 保证 bounce 端点高度为 0，且整段轨迹不穿过场地地面。
- 让未知起点/终点使用方向正确的开放视觉弧，而不是复制另一端高度。
- 引入逐事件击球高度的证据来源、置信度和不确定度；无证据时仍可使用全局先验，但必须明确是低可信视觉估计。
- 让 artifact、前端 view model 和 Three.js 场景保留高度有效性与置信度语义。
- 保持历史 v1/v2/v3/v4 artifact 可读，不回写已完成任务，并为真实 v4 样本增加回归覆盖。

**Non-Goals:**

- 不在本变更中修复球检测模型、双摄匹配、Homography 标定或场外点分类算法。
- 不把单摄 2.5D 高度升级为真实三维测量，也不因此开放真实最高点或球速指标。
- 不将负高度简单裁剪为 0；无效 3D 应降级、拒绝或保留为诊断证据。
- 不根据球场区域、击球者身份或固定拍型规则臆造接触高度。
- 不改变现有事件切段、Shot 归属和场外坐标保留策略。

## Decisions

### 1. 在后端采用“硬边界 + 发布校验 + 前端防御”的三层保护

3D 优化的控制点使用 `z >= 0` 的优化边界，bounce 端同时保留 `z=0` 端点约束。优化完成后，以密集采样检查整条 spline 的最小高度、非有限值、端点高度和高度跳变；任何检查失败的 3D 段都不得继续标记为可用 `stereo_estimated_3d`。

发布层优先将失败段交给同段合格的 2.5D 重建；若 2.5D 也不满足最低条件，则标记 `unavailable` 并保存拒绝原因。前端仍对历史或异常 artifact 做负值/非有限值防御，防止不可信数据直接生成几何。

选择三层保护而不是只在前端裁剪，是因为前端裁剪会掩盖后端质量问题，且视频、报告和其他消费者仍可能读取非法高度；只在优化器加边界又无法保护历史产物或序列化边界。

### 2. 用端点状态显式驱动 2.5D 高度函数

高度函数不再通过“缺失端复制已知端”补齐，而是根据起止端状态选择形状：

```text
known start, known end   z0 → peak → z1
known start, unknown end z0 → peak → open end
unknown start, known end open start → peak → z1
unknown, unknown        不生成正式高度曲线
```

`bounce` 端为硬 `0`；`hit`/`serve_reset` 端为有来源标记的正高度；`loss`/`unknown` 端不伪造精确落地。仅终点有锚点时使用起点方向反向的 smoothstep/二次弧，确保终点对齐且轨迹在中段有高度变化；仅起点有锚点时保留现有朝未知端展开的开放弧。未知区间的 `height_confidence` 逐渐降低，供前端弱化而不是改变事件语义。

### 3. 采用证据优先的逐事件接触高度

击球高度的来源优先级为：

1. 在事件时间窗内存在合格双摄高度证据时，使用该证据的稳健值；
2. 有可验证的图像/球员上下文垂向证据时，使用经过范围限制的视觉估计；
3. 否则使用现有 `default_contact_height_m = 1.10` 全局先验。

所有来源都必须经过 `0.45–2.40m` 范围限制，并写入 `height_source`、`height_confidence`、`height_uncertainty_ft`。全局先验可作为兜底，但不能被描述为实际测得的击球点高度。未能获得逐事件证据时，优先保证弧线形状和不确定性表达，而不是生成虚假的精确高度差异。

选择证据优先而不是按球场区域调参，是因为区域与击球高度没有稳定的一一对应关系；选择兜底先验而不是直接丢弃，是为了保留 visualization-only 的可读球路。

### 4. 使用加法式 artifact 字段保持历史兼容

继续使用 `reconstructed_ball_trajectory.v4` 作为读取入口，新增或规范化可选字段，不修改历史任务文件。段级增加高度约束状态/原因，样本级保留已有高度来源、置信度和不确定度，并补充高度有效性语义，例如 `valid`、`invalid_below_ground`、`unknown_open_end`。

旧 artifact 缺失这些字段时按旧规则读取，但前端仍执行最基本的有限值和非负高度保护；新 artifact 必须通过发布校验后才允许声明对应的 3D/2.5D 展示资格。

### 5. 前端只负责安全消费和可信表达，不重新生成物理高度

`ballTrajectoryVisualization` 保留 `heightConfidence`、来源和有效性；`BallTrajectoryScene` 在构建几何前过滤无效高度，并对低置信度高度降低透明度或使用弱化线型。前端不得把负高度吸附到地面，也不得为缺失高度重新生成一条统一抛物线。

这保持“后端 artifact 是唯一高度来源”的架构，同时为历史任务和 API 异常提供最后一道安全边界。

## Risks / Trade-offs

- [硬高度门会减少部分 3D 可见段] → 将不合格段降级到同段 2.5D，并在诊断中保留原始 3D 失败原因。
- [逐事件接触高度仍可能是估算] → 强制保存来源、置信度和不确定度；visualization-only 段不开放真实最高点和速度。
- [开放弧的视觉形状可能与真实球路不同] → 明确标记未知端和视觉估计，使用确定性函数，避免制造精确落点或落地结论。
- [旧 artifact 可能包含负高度] → 读取时执行前端防御；正式质量统计不把非法高度段计入合格 3D，历史文件本身不回写。
- [双摄证据在事件时刻稀疏] → 只有通过质量门的证据才用于接触高度；否则回退到低可信先验，不阻断单摄球路交付。

## Migration Plan

1. 先扩展高度字段和前后端解析器，保持旧 artifact 读取。
2. 为 3D 优化器增加非负参数边界、密集采样校验和失败状态；为 2.5D 重建增加未知端方向函数和逐事件高度来源。
3. 在混合段组装与 artifact 发布边界接入高度质量门，非法 3D 段自动降级或不可用。
4. 更新前端 adapter 和 WebGL 防御逻辑，确保负/非有限高度不生成几何，并使用高度置信度弱化开放区间。
5. 使用 `job-71166f62f7` 及现有 fixture 执行回归：不得出现负高度展示；bounce 端为 0；单锚点不恒高；历史 artifact 仍可读取。
6. 若新高度门导致展示质量异常，可通过关闭新混合发布开关回退到旧读取路径；不删除新诊断字段或既有任务产物。

## Open Questions

- 当前素材是否具备足够的球员姿态/图像垂向证据，能够在不引入新模型的情况下估计逐事件击球高度？
- 接触高度证据的最小置信度和事件时间窗应如何用真实样本标定？
- 对负高度 3D 段，默认优先降级为 2.5D，还是在 3D 质量过低时直接标记不可用？提案默认优先降级。
