## Context

系统为 React/Vite 前端、FastAPI API、独立 analysis-worker、本地文件资产和 SQLite 控制面。2026-09-06 审核以含未提交候选复核功能的工作区为基线。实施前须重新查看 git diff，不覆盖或回退这些既有改动。

已复现：路径型摄像头 ID 越界落盘；MOV/WebM 流响应使用未赋值变量；候选决定写 JSON 后数据库回滚仍为 accepted；候选重生成后旧决定匹配到同名新候选。代码审查另确认 JobStore 读取全量扫描/写盘、投影开关未接入、异步上传同步抽帧。后端测试失败是 StubLockManager 缺少 slots，不作为真实算法故障。

## Goals / Non-Goals

**Goals:**
- 主流程失败可见，复核决定与正式片段一致，来源能追溯到实际接受的候选版本。
- 文件操作严格在配置根目录内，凭据不进入公开响应和页面。
- 逐帧检查成本不随历史任务数线性增长，关闭诊断时无对应产物开销。
- 基础环境可安装、可启动、可自动验证；可选模型配置独立说明。
- 首屏不预载全部重型工作台，现有深链、demo 边界与录制语义保持稳定。

**Non-Goals:**
- 不重新训练或评估算法准确率，不改变比分、同步映射、场地坐标及身份锁定策略。
- 不引入分布式队列、账号/权限体系，不宣称具备公网部署条件。
- 不全面拆解 analysisClient/report 类型和所有大组件，不删除旧路由，不改写无关历史规格。

## Decisions

### 1. 摄像头路径：配置根目录加双层校验

使用 Settings.resolved_cameras_dir；schema 和服务层共用 ID 校验，拒绝空白、控制字符、斜杠、反斜杠、绝对路径及 `.`/`..`，保留合法中文、空格和既有安全 ID 的兼容性。拼接后 resolve 并验证相对于配置根目录的归属，拒绝指向目录外的符号链接。创建使用排他写入或原子不覆盖策略，避免检查后覆盖。

不采用仅 Path.name 截断：它会把不同非法输入静默变成同一个 ID。历史配置通过显式迁移命令导入，默认 dry-run；只枚举给定可信旧目录的普通 JSON，验证文件名/内容 ID 一致、安全且目标不冲突。相同内容跳过，不同内容报告冲突，原文件和引用保持可追溯；非法 ID 不自动改名。

API 序列化统一移除 stream_url userinfo，独立 password 保持掩码；内部连接使用原值，错误响应/日志也不透传带凭据 URL。不通过隐藏前端文本替代服务端脱敏。

### 2. 候选复核：SQLite 为唯一决定真源

增加候选 artifact 快照表、复核版本表和决定表，纳入现有 app.sqlite3 迁移链路：

| 实体 | 关键字段与约束 |
|---|---|
| artifact 快照 | take_id、artifact_version（原文件 bytes 的 SHA-256）、不可变内容、来源/模型、创建时间；唯一 take_id + artifact_version |
| 复核版本 | take_id、artifact_version、revision；事务内条件更新 |
| 决定 | request_id、candidate_id、decision、边界、provenance、operation_id、output_segment_id、revision、请求摘要；request_id 唯一，take_id + artifact_version + candidate_id 唯一 |

候选读取先将一次性读入的文件 bytes 校验 schema、take 归属、候选 ID 唯一性和数值边界，再基于同一内容计算版本与快照。重新生成或修改任何内容都会形成新版本；即使只修改格式也重新复核，这是偏保守但易审计的选择。不采用模型名或顺序 candidate ID 作为版本。

决定请求增加 `artifact_version`、`request_id`，保留 `expected_revision`。处理顺序：先检查同一 request_id 的已提交请求；内容相同返回原结果（即使当前 artifact 已更新），内容不同返回 409。新请求解析当前 artifact，版本不符返回 `candidate_version_conflict`；通过数据库条件更新串行化同版本复核，revision 不符或候选已决定返回 409；在同一事务写决定、编辑操作、片段及 ordinal 修改。提交前任何失败全部回滚。

成功决定绑定请求校验时读取的不可变快照。推理进程随后替换文件不改变已提交决定，也不会将其应用到新文件。不同版本接受的新区间仍走既有正式片段重叠校验，不自动删除旧片段。

JSON reviews 降为可重建导出，不参与读路径权威判定；采用唯一临时文件、原子替换，导出失败只告警并允许重导，不回滚成功事务或把 API 成功变成失败。拒绝仅产生决定和审计，不新建片段。接受/修正沿用 manual_rally 的业务校验；不隐式改变现有边界复核的 confirmed 语义，不直接纳入训练真值。

前端每次加载保存 artifact_version；一次保存生成并保留 request_id，网络结果不明时用同一请求重试；409 后刷新候选和 revision，保留用户草稿提示但不得自动把旧草稿提交给新版本。

不采用给 JSON 加锁作为主要修复：文件锁无法与数据库形成统一提交。SQLite revision 条件更新须在业务插入前取得写入权，锁超时作为可重试错误返回，不允许部分提交。

### 3. 历史复核迁移：保留证据，不猜测确认关系

先备份数据库及 reviews/timeline 文件并输出迁移清单。旧记录通常没有完整 artifact 哈希，不能仅凭 package_id、candidate_id 或起止点推断与当前版本相同：此类记录导入为 legacy_unbound 审计，不覆盖当前候选状态；正式片段保持原样。若历史记录确有完整版本及对应快照且所有身份、操作、片段引用可验证，则幂等导入为绑定决定。冲突/断裂引用留待人工处理。

旧 accepted JSON 但无正式片段的记录不补造片段；不得重新执行接受动作来“修复”历史。迁移可重复且记录原文件哈希。

### 4. 视频响应与上传边界

保留已有 faststart/merged 路径优先级，按最终选中路径确定 MIME：mp4/m4v→video/mp4，mov→video/quicktime，webm→video/webm，avi→video/x-msvideo，mkv→video/x-matroska，ts→video/mp2t，未知类型安全回退 application/octet-stream。服务正确传输不等于浏览器支持所有编码，不自动转码；页面对不支持编码给出可恢复错误。

保留受控文件句柄的流式实现，提取纯 Range 解析器并测试：正常完整请求 200；闭区间/开放区间/后缀单范围 206；不可满足范围和空文件范围请求 416 + `Content-Range: bytes */size`；非法单位、语法返回 400；合法多范围本次忽略 Range 返回完整 200（不伪造单范围）。支持 HEAD 返回与 GET 对齐的响应头，无响应体。客户端中断后释放句柄。

上传大小上限以 `PICKLEBALL_MAX_UPLOAD_BYTES` 配置，初始默认 20 GiB，可正整数覆盖；声明长度只做提前拒绝，实际累计字节是最终限制。API 入站增加覆盖 multipart 的流量计数边界，包含 1 MiB multipart 开销预算，避免框架先缓存无限请求；业务层再检查文件净大小。超过返回 413，空文件返回 400。临时写入、登记失败、客户端中断均清理本次文件，成功持久化后才进入目录。

封面先使用受限线程池 offload 现有抽帧函数（并发上限默认 2），保留超时与失败降级。本变更不引入持久化封面队列；请求可等待线程完成，但 API 事件循环必须能服务其他请求。用同步屏障验证健康请求先于抽帧释放完成，避免依赖脆弱耗时断言。

### 5. JobStore 查询不兼任迁移与快照同步

从 get/list/取消检查移除 `_import_legacy_jobs()`；启动迁移一次，记录完成标记；后续新增历史文件只能通过显式重导命令导入。导入仅 insert-if-missing，不覆盖控制面，坏文件隔离日志，跨进程重复启动幂等。

get/list 只读 SQLite 并构造返回模型；兼容 JSON 快照仅在状态实际变更后原子写入。取消检查直接读取该 job 的 cancel/status 字段，避免全模型序列化和文件持久化，跨进程取消、lease 和终态规则保持原样。计时对比作为诊断，门禁以操作计数为准：1/100/1000 个历史记录下固定次数查询，JSON read/write/扫描均为零，数据库查询次数恒定。不通过长期缓存掩盖取消可见性。

投影 JSONL 和 overlay 独立受既有开关控制；全部关闭时不初始化 writer/minimap，不创建对应目录或文件。分别开启及组合开启验证产物和 finally 释放，不改正常报告图表。

### 6. 交付环境与自动门禁

以 backend/pyproject.toml 为后端依赖源，补齐 SQLAlchemy 和被正式支持入口实际导入的依赖；requirements 从此生成，根 pyproject 不再声明冲突的后端解释器范围。第一条受验证基线选 Python 3.11；基础环境与 vision/pose/训练环境分开，按平台生成锁定解析结果并记录生成命令。不得把当前个人环境 freeze 成唯一安装规范。

基础 CI 使用 Node 22、Python 3.11、FFmpeg，无 GPU/模型；提交可复现锁文件后在干净环境安装，验证包安装和 requirements 路径。统一后端根目录入口并兼容 README 的 `cd backend && python -m pytest -q`，解决 root/scripts 的导入路径冲突，不以忽略失败文件通过门禁。修复 StubLockManager 契约但保留正式/候选集合互斥断言。

CI 执行 npm ci/build/test（maxWorkers=2）/lint、完整基础 pytest、OpenSpec 校验。测试开始前配置所有目录/控制数据库/静态目录，清空单例缓存；移除摄像头和测试帧目录硬编码，禁止访问真实摄像头/个人素材。CI 中基础测试失败不可跳过，真实硬件/模型检查必须单独标记；外部条件不足记录未验证而非通过。

默认本地启动选择基础模式：关闭模型/姿态/自动场线模型依赖，仍启动 API+Worker+前端；显式启用模型时要求路径、依赖预检成功，失败在拉起进程前退出。API/Worker 使用同一份解析配置，保留端口冲突、回滚、优雅停止和默认 loopback。

### 7. 前端加载预算与能力说明

保留 landing/应用壳初始加载，工作台页面动态导入；排查 Library/shared 模块反向静态导入重型页面，不能只改 AppRouter 就宣称完成。共享图表/3D 内容按消费边界加载，维持 URL、return/search、历史与错误降级语义。设置 Suspense 和 chunk 错误边界，可重试或刷新恢复。

验收预算为 landing 冷加载入口及其所有静态依赖的 JS gzip 合计 ≤350 KiB（排除 source map，CSS 单列），同时记录全部 chunk 大小；不得通过单纯改 chunk 名称绕过统计。不对尚未实测的首屏时间承诺数值。

README 与技术说明统一真实/实验/演示/规划能力，硬件页保留明确模拟标识；已有真实失败不回退 demo 的测试继续保留。日志/门禁记录为验收证据，不以测试数量或格式校验代表算法有效性。

## Risks / Trade-offs

- 旧复核无完整版本，迁移后出现待复核候选 → 保留正式片段，明确 legacy_unbound，禁止自动重做接受造成重复。
- SQLite 写并发存在等待 → 短事务、唯一约束和条件更新，真实独立连接测试竞争与回滚。
- 调试默认关闭改变历史产物集合 → 缺失调试产物按既有 unavailable/404 处理，复核报告不依赖调试文件。
- MIME 修复不能解决浏览器编码不支持 → 分别验收协议响应和真实浏览器可播素材。
- 首包预算需要跨共享组件调整 → 仅按加载边界拆分，保留现有导出，避免顺带重构全部业务逻辑。
- 可选模型栈的平台兼容性未知 → 独立安装档案，实际验证后再声明支持；基础 CI 不证明 RTMPose 可运行。

## Migration Plan

1. 实施前记录工作区基线与未提交文件归属；在临时资产副本上验证迁移，不启动真实录制。
2. 第一阶段先恢复测试入口并添加缺陷回归，完成摄像头安全、复核事务/版本与视频流修复；所有新增写路径在隔离测试通过后才接入 UI。
3. 停止新复核写入，备份 app.sqlite3（使用 SQLite 安全备份）、候选和摄像头配置；执行 schema 迁移与历史 dry-run，核对清单后执行可重复导入。API 与前端同步升级候选请求契约。
4. 第一阶段验收通过后实施热路径、调试开关与上传边界；第三阶段完成依赖/启动、CI 干净安装、首包与文档收口。
5. 回滚先暂停写入并备份升级后数据库；保留新增表和不可变候选证据。若回到不理解事务复核的旧代码，应禁用候选决定入口，不恢复旧 JSON 为权威；需要完整恢复时从升级前备份恢复并单独保存升级后新增决定，禁止直接丢弃新记录。摄像头原配置保留，迁移不会删除源文件。

## Open Questions

无阻塞提案生成的问题。20 GiB 上传默认值、350 KiB 首包预算与 Python 3.11 基线为本提案采用的明确初值；实施中若样本规模或干净安装证据要求调整，先更新本设计及对应规格/任务并说明证据。真实模型、双摄和不同浏览器的验收环境由实施时可用资产决定，未具备条件须列为未验证。
