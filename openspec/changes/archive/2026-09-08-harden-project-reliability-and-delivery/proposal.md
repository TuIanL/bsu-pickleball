## Why

2026-09-06 对当前工作区的审核复现了摄像头目录越界写入、候选复核跨版本误继承与数据库回滚后状态残留、MOV/WebM 播放异常；同时确认逐帧任务读取存在全量扫描写盘、调试开关失效及质量门禁问题。需要先恢复数据可信性和主流程稳定性，再改善性能与可复现交付，避免继续扩展功能放大既有缺陷。

## What Changes

- 第一阶段：约束摄像头 ID 与配置目录、完整脱敏连接凭据；把模型候选复核与正式片段放入同一事务，绑定不可变候选版本，处理并发、重试和历史记录迁移。
- 第一阶段：修复源视频 MIME 与单范围 Range 响应，恢复后端测试入口和失败的测试替身契约，建立隔离的自动质量门禁。
- 第二阶段：将历史任务迁移和快照写入移出逐帧读取路径；接通投影诊断开关；将封面生成移出 API 事件循环，并限制上传大小、清理失败残留。
- 第三阶段：统一后端依赖声明、锁定可运行环境，提供无需模型的基础启动与显式模型配置；按路由拆分前端首包，统一产品、实验和硬件演示的说明。
- **BREAKING**：新增/改名摄像头将拒绝路径型 ID；候选决定请求必须携带候选版本及幂等请求 ID；无法证明来源的旧复核记录保留审计用途，但不自动标记新候选为已确认。
- 不在本变更中新增算法、训练模型或账号系统；不删除硬件演示路由、不全面重写巨型模块、不批量改写全部历史规格 Purpose。局域网/公网多人部署另立访问控制提案。

## Capabilities

### New Capabilities

- `source-video-io-reliability`：源视频 MIME、Range、上传资源限制与不阻塞事件循环的封面生成契约。
- `project-delivery-quality-gates`：可复现依赖、隔离测试、持续集成、构建预算和对外能力说明的验收契约。

### Modified Capabilities

- `camera-ingest-management`：配置目录为唯一写入根、摄像头标识约束、历史迁移与响应凭据脱敏。
- `learned-match-state-segmentation`：候选版本绑定、复核事务、并发与幂等、旧 sidecar 兼容策略。
- `analysis-job-orchestration`：历史导入仅在显式迁移边界发生，运行期查询与取消检查无历史扫描或持久化副作用。
- `local-runtime-commands`：默认基础启动可缺少模型，显式启用模型时预检失败，API/Worker 配置一致。
- `frontend-architecture-boundaries`：页面按需加载及加载失败恢复，保留现有深链与导航语义。

## Impact

- 后端：camera registry/API、候选复核 API/service/数据库迁移、视频上传与流播放、封面生成、JobStore/控制面、analysis pipeline、配置与测试。
- 前端：候选复核请求与冲突恢复、摄像头校验提示、视频错误状态、AppRouter 和共享结果组件的加载边界。
- 工程：backend 依赖清单与锁文件、启动脚本、CI、README/技术成果说明。兼容现有 npm lock 和本地优先架构，不引入 Redis/Celery。
- 数据：保留已有视频、正式片段、复核原始文件和模型权重；迁移须可重复、可审计且先备份，冲突不得静默覆盖。
- 现有 `projection-diagnostics` 的关闭行为要求保持不变，本次补齐实现与回归场景，不重复新增同义规格。
- 审核基线：前端 670 项通过；后端从根目录执行为 1457 通过/1 失败/1 跳过；187 份 OpenSpec 格式通过。测试数量不是算法准确率证明，真实摄像头与模型验收单独记录。
