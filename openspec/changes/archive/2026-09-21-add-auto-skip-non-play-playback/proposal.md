## Why

片段页现在把整个 CaptureTake 原样播出——包括分与分之间的发球准备、暂停、换边。想连续看多个回合时，用户必须每打完一分就手动把进度条拖过中间的空白，一分一次，不可持续。

要跳过的那部分数据本来就有：已发布的正式切分 run 提供了 algorithm 回合区间，区间之外就是用户定义的「非比赛时间」。缺的不是数据，是一个开关和续播编排。

## What Changes

- **「非比赛时间」的口径**：已发布切分 run 的 active algorithm 回合区间之外的**全部时间**。它包含分间发球准备、暂停与换边、模型未判定的区段，以及被 500ms 最短时长规则压制的漏检回合。这是一个刻意的选择——数据全部由前端现成推导，不需要新增接口；代价是被模型漏检的真实比赛内容也会被跳过。
- 片段页新增**「自动跳过非比赛时间」开关，默认开启**：
  - 开关开启时，片段**自然播放到有效终点**后不停下，而是跳到下一个 algorithm 回合的起点继续播放；最后一段播完则停在终点暂停，**不循环回开头**。
  - 开关关闭时，完全保持既有行为（播到有效终点自动暂停）。
- **拖动定位不受影响**：开关开启时进度条与时间线仍可自由定位到任意位置，包括非比赛区间；跳转**只由「片段自然播完」触发**。因此手动把播放头拖进非比赛区间后按下播放**不会**自动跳走——这是「弱约束」的直接结果，需要在规格里显式定义而不是留给实现去猜。
- **逐帧越过段尾不算「自然播完」**，不触发跳转。
- 中央「第X回合」提示在**自动续播**引起的连续跳转时**合并为一块**：显示窗口内的多次变化只就地更新文字为最新序号，不重新淡入淡出；并设最小静默间隔，避免「刚淡出又立刻淡入」造成的双闪。用户主动点击或拖动引起的回合变化**永远提示**，不受该规则抑制。
- **进度条配色不变**——仍是自动回合 / 非回合两色。在补集口径下「非回合区间」与「将被跳过区间」恒等，第二色本身就是跳过标识，无需第三色。
- **内部边界复核隔离模式（`?mode=boundary-review`）强制不启用**该开关，保证复核时能停在边界查看前后帧。
- 无正式切分结果时开关**禁用并给出原因**，不静默无效。
- **BREAKING**：默认开启会改变普通片段页的默认播放行为——点击一个片段播到终点后不再停下，而是继续播下一段。这是对本变更下两份既有规格「播到有效终点自动暂停」的**条件性覆盖**，本变更会同步修改这两份规格使语义保持自洽。

## Capabilities

### New Capabilities

- `auto-skip-non-play-playback`: 定义回合间隙的自动跳过开关——非比赛时间的推导口径、开关的默认状态与可用性降级、开启时的续播与停止规则、拖动与逐帧的边界、以及连续跳转时中央回合提示的合并规则。

### Modified Capabilities

- `segment-playback-editing-sync`: 「片段播放完成后自动暂停」加入条件——仅在自动跳过开关关闭时成立；开启时改为续播到下一个回合区间，末段停止。
- `segment-manager`: 「片段管理页保持播放头和列表高亮同步」中的「播放自动停止」场景加同一条件。

## Impact

- 前端（组件层）：`src/components/SegmentVideoPlayer.tsx` —— 拆分「自然播完」与「被中断」两种完成语义；新增开关控件（按数据可选启用）；提示合并与最小静默间隔。
- 前端（页面层）：`src/pages/SegmentManagerPage.tsx` —— 开关状态与默认值、非比赛时间（回合补集）推导、续播编排、复核模式下的强制禁用。
- **无后端、无 API、无数据字段、无数据库改动**：跳过逻辑完全建立在已发布的 algorithm 回合之上。
- 不受影响：`EditableSegmentTimeline`、进度条配色、`ScoringCalibrationWorkbenchPage`（不传开关即不出现该控件，行为与引入前一致）。
- 依赖：复用已归档的 `auto-rally-playback-cues` 的回合数据口径与提示时机，但不修改其规格。
