## Context

现有分析流水线会输出 `cleaned_ball_trajectory.json`、`ball_trajectory.json` 和 `bounce_events.json`，前端通过现有 API 按任务读取。轨迹点包含时间、图像坐标、二维球场坐标、置信度和插值标记，但不存在真实高度、回合切分或三维重建结果。项目当前使用 React 19 和 Vite，二维位置图由 SVG 渲染，尚未引入 Three.js。

本次变更只消费已有 artifact，不要求重新分析历史任务，也不改变后端存储合同。主要使用者是查看单个分析任务的教练、运动员和演示人员。

## Goals / Non-Goals

**Goals:**

- 把有效二维球场轨迹转换为稳定、可测试的渲染球路。
- 提供包含标准匹克球场、球网、球路和事件点的交互式 2.5D 视图。
- 明确区分检测点、插值点和估算高度，避免将视觉拟合表述为真实测量。
- 在桌面和移动视口中提供稳定尺寸、预设视角、筛选、全屏和完备状态。
- 复用现有任务 API，使已有清洗轨迹可直接展示。

**Non-Goals:**

- 不进行双目空间标定、三角化或真实高度恢复。
- 不声称提供真实最高点、过网高度、三维速度或正式落点判定。
- 不在本次变更中新增击球识别、回合识别或球员击球归因。
- 不修改现有球检测、轨迹清洗、弹跳检测或二维可视化输出。

## Decisions

### 使用纯前端适配器生成渲染球路

页面读取现有分析结果、清洗轨迹和弹跳 artifact 后，在无副作用的 TypeScript 服务中完成点清洗、排序、分段、抽样和高度拟合。选择前端派生而不是新增后端 artifact，是因为本阶段数据只服务展示，现有历史任务也能立即使用，并且不引入迁移成本。

适配器仅接受有限数值和合理球场范围内的点；按时间间隙与不合理的平面跳变断段；过滤点数不足的段；为每段计算平均置信度、插值比例和方向。渲染点保留原始二维坐标，不覆盖源 artifact。

### 高度使用明确标注的确定性抛物线拟合

每段使用归一化进度 `p` 和 `z = 4 * peak * p * (1 - p)` 生成视觉高度。`peak` 根据平面距离与持续时间在保守范围内截断，使相同输入始终生成相同输出。该字段命名和 UI 文案均使用“估算高度/2.5D”，渲染数据来源标记为 `estimated`。

备选方案是只显示贴地二维线条，但无法达到目标视觉表达；随机或复杂物理模拟会制造不可重复且更容易被误认为真实的数据，因此不采用。

### 使用 Three.js 直接管理场景生命周期

新增 `three` 依赖，React 组件通过 `ref` 创建场景、正交相机、渲染器、轨道控制器、标准球场几何和球路线条，并在卸载时释放几何体、材质、控制器和 WebGL renderer。直接使用 Three.js 可减少本阶段额外抽象层，同时满足预设相机视角和全屏渲染需求。

相机采用正交投影，避免透视变形妨碍落点比较；球场按 20 ft × 44 ft 的真实比例构建，世界坐标采用 `x=球场宽度`、`y=高度`、`z=球场长度`。

### 页面归属于分析任务

新增 `/analysis/{jobId}/trajectory`，从任务的视觉分析页面进入。页面自行读取任务和 artifact，避免把大对象写入路由状态，也保证刷新和分享 URL 后仍可恢复。无任务数据时展示诊断状态，不生成演示轨迹冒充真实分析结果。

### 轨迹数量默认受控

为避免长视频产生过多 GPU 几何，适配器限制单段抽样点和默认可见轨迹数量，页面允许查看全部或仅查看较高可信度轨迹。线条按方向使用两种可访问颜色，低可信度轨迹降低透明度，弹跳候选单独显示。

## Risks / Trade-offs

- [空中球被地面单应性错误投影，二维位置本身可能偏移] → 页面持续展示“估算 2.5D”说明，并暴露置信度，不输出精确高度指标。
- [检测间隙可能把一次球路拆成多段，或把相邻球路合并] → 使用保守阈值与确定性分段，并让用户按轨迹单独检查；后续可用击球/回合事件替换启发式切分。
- [长任务轨迹过多导致 WebGL 性能下降] → 限制抽样点与初始显示数量，几何按轨迹复用单个材质并在变更时释放。
- [WebGL 不可用或 context 丢失] → 显示可恢复的错误状态，并保留返回视觉分析页面的入口。
- [Three.js 增加前端包体] → 页面级懒加载球路页面，使主分析页面不承担 3D 依赖的首屏成本。

## Migration Plan

1. 新增前端依赖、适配器、组件、页面和任务级路由。
2. 在视觉分析页面增加球路入口，不改变现有默认页面。
3. 运行适配器和路由测试、TypeScript 构建与浏览器渲染检查。
4. 若出现兼容性问题，可移除入口和新路由；现有 artifact 与分析流程不受影响。
