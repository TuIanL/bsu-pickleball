## Why

正式自动回合切分已进入双摄 `match_default` 的必经阶段，并把结果以 `source=algorithm` 的 Rally Segment 发布到 CaptureTake 上；但片段页只把这些回合平铺在右侧列表里，回放面上没有任何与之同步的位次提示。用户看视频时无法判断「现在播到第几回合」，必须不断回看列表、比对时间戳。播放器下方那条进度条也仍然是一条无结构的单调进度条，看不出整段视频里哪些区间是回合、哪些是回合之间的间歇。

结果是刚落地并被刻意收敛为正式产品能力的自动切分，在用户实际看回放时几乎不可感知。补齐这件事不需要任何后端改动——数据已经在了，缺的只是前端的回放提示。

## What Changes

- 片段页播放器新增**当前自动回合的中央叠加提示**：
  - 播放头所属的「当前已发布切分 run 的 active algorithm Rally」发生变化时，在视频画面正中央叠加一次「第X回合」大字，随后淡出；同一回合内不重复出现。
  - `X` 取该 Rally 的 `ordinal`，不重新编号、不按筛选后的列表位置推算。
  - 高不透明度白字加深色描边，保证在明亮画面上仍清晰可读；叠加层不接收指针事件，不拦截播放器既有的播放/暂停、逐帧、快捷键行为。
  - 仅覆盖 `source=algorithm` 的回合；现场人工片段与人工关键事件不触发叠加。
- 片段页播放器进度条新增**回合区间配色映射**：
  - 以两种颜色区分「自动回合区间」与「非回合区间」，按媒体总时长归一化映射到进度条轨道上，直观呈现切分结构。
  - 保留原生拖动定位交互，并保留「已播放 / 未播放」这一读数（以半透明遮罩表示已播放部分），不与区间配色互相覆盖。
- **新增能力全部按可选启用实现**：`SegmentVideoPlayer` 是共享组件（另一个调用点是评分标定工作台），未传入自动回合数据时，组件的渲染结果与交互行为与现状完全一致。
- **非目标**：不改后端、不改切分算法、不新增 API、不改动片段列表与页面底部「时间线」区块的现有三轨样式，也不变更任何既有页面的既有行为。

## Capabilities

### New Capabilities

- `auto-rally-playback-cues`: 在片段回放面上呈现当前已发布正式切分 run 的自动回合信息，包含两组行为——播放头进入新自动回合时的中央「第X回合」瞬时叠加提示，以及播放进度条上的自动回合/非回合区间配色映射。

## Impact

- 前端（页面层）：`src/pages/SegmentManagerPage.tsx` —— 独立推导「当前已发布 run 的全部 active algorithm Rally」集合与「播放头当前所属回合」，并把结果作为可选数据传给播放器。该集合不受片段列表上方筛选器影响，也不混入人工片段。
- 前端（组件层）：`src/components/SegmentVideoPlayer.tsx` —— 新增中央叠加层、进度条分段色带与已播放遮罩；新增的 prop 全部可选，缺省时组件行为与现状逐项一致。
- 前端（样式层）：`src/index.css` —— 新增进度条轨道与滑块的自定义样式，用于在接管原生轨道渲染的同时保住可拖动性。
- 不受影响：`ScoringCalibrationWorkbenchPage`（同一播放器组件的另一调用点，不传新 prop）、`EditableSegmentTimeline`、后端与全部 API 契约。
- 数据依赖：消费 `formal-match-state-segmentation` 已定义的发布契约（`source=algorithm`、`segmentation_run_id`、`ordinal`、`label`），不新增字段。
